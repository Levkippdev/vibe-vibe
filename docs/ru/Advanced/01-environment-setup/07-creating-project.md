# 1.7 Создание проекта

> **Прочитав этот раздел, вы получите:**
>
> - Правила именования папок и способы избежать проблем разработки из-за китайских путей
> - Как пользоваться официальным scaffolding-инструментом для быстрого создания стандартной структуры проекта
> - Понимание структуры каталогов проекта Next.js

Самая частая ошибка новичков — вручную создавать файлы AI-сгенерированного кода один за другим. Правильный подход — использовать шаблон проекта и позволить AI создать стандартный проект через scaffolding-команду.

## Подготовка

### Создайте папку проекта

Перед созданием проекта сначала создайте в файловом менеджере папку с **исключительно английским путём**.

**Важно**: ни один уровень полного пути не должен содержать китайских иероглифов или пробелов.

| Неверный пример | Причина |
|----------|------|
| `C:/Users/张三/projects` | Имя пользователя на китайском |
| `C:/Users/李/my project` | В имени папки пробел |

| Верный пример | Примечания |
|----------|------|
| `C:/Users/YourName/projects` | Всё английское, без пробелов |
| `/Users/yourname/projects` | Пользовательский каталог macOS |

**Рекомендуемая структура папок**:

```
my-projects/          ← Главная папка
├── my-first-app/     ← Проект 1
├── blog-app/         ← Проект 2
└── store-app/        ← Проект 3
```

### Откройте terminal в этой папке

Создав папку, нужно открыть внутри неё terminal для выполнения команд.

| Система | Действие |
|------|------|
| **Windows** | Правый клик по пустому месту в папке → «Open in Terminal» |
| **Старые Windows** | Зажать `Shift + правый клик` → «Open PowerShell window here» |
| **Mac** | Finder → Services → New Terminal at Folder |
| **IDE** | Cursor/VS Code/Trae: File → Open Folder, встроенный terminal находит папку автоматически |

### Что такое путь файла

Путь файла — это расположение файла в файловой системе. Когда вы говорите AI «измени src/app/page.tsx», AI должен найти этот файл по его пути.

**Абсолютный путь**: полный путь от корневого каталога

```
Windows:  C:\Users\YourName\projects\my-app\package.json
macOS:    /Users/yourname/projects/my-app/package.json
```

**Относительный путь**: путь от текущего каталога

```
./package.json        # package.json в текущем каталоге
../other-project      # other-project в родительском каталоге
src/app/page.tsx      # src/app/page.tsx в текущем каталоге
```

## Правила именования

Инструменты разработки плохо работают с китайскими путями, что легко приводит к самым странным ошибкам.

| Верно | Неверно |
|----------|----------|
| `my-project` | `我的项目`, `my project` |
| `user-profile` | `user profile`, `用户资料` |
| `app.tsx` | `应用.tsx`, `app 文件.tsx` |

**Правила**:

- ✅ Используйте строчные английские буквы
- ✅ Используйте дефисы `-` для разделения слов
- ❌ Избегайте китайских иероглифов, пробелов и спецсимволов

::: tip Почему нельзя по-китайски?

**Частые ошибки**: `ENOENT: no such file or directory`, `MODULE_NOT_FOUND`

Китайские пути могут вызывать проблемы кодировки, ошибки парсинга путей и несовместимость инструментов.

:::

## Создайте проект

Все современные фреймворки предоставляют официальные scaffolding-инструменты. Стандартный проект создаётся одной командой.

```bash
# Создать Next.js-проект (my-app — имя проекта, можно поменять)
pnpm create next-app@latest my-app

# Создать Vite + React проект
pnpm create vite@latest my-app -- --template react
```

При создании спросят про опции конфигурации:

- **TypeScript**: рекомендуется выбрать Yes
- **ESLint**: рекомендуется выбрать Yes
- **Tailwind CSS**: по вашим потребностям
- **Каталог src**: рекомендуется Yes (код в `src/` — структура яснее)
- **App Router**: рекомендуется Yes

::: tip Не хотите запоминать команды?

Если команду не удаётся запомнить, просто скопируйте пример из этого туториала. Но команда простая, так что рекомендуется её выучить:

```bash
pnpm create next-app@latest my-app
```

:::

## Структура Next.js-проекта

После завершения создания вы увидите примерно такую структуру:

```
my-next-app/
├── src/
│   ├── app/                 # Страницы и API
│   │   ├── page.tsx         # Главная страница
│   │   ├── layout.tsx       # Глобальный layout
│   │   └── api/             # API endpoints
│   │
│   ├── components/          # UI-компоненты
│   └── lib/                 # Утилитарные функции
│
├── public/                  # Статические ассеты (картинки, шрифты)
├── package.json             # Управление зависимостями
└── tsconfig.json            # Конфигурация TypeScript
```

**Простое объяснение**:

- `src/app/` — файлы страниц и endpoints
- `src/components/` — переиспользуемые UI-компоненты
- `src/lib/` — утилитарные функции
- `public/` — статические ассеты вроде картинок

::: tip Куда класть код?

Когда AI говорит «создай страницу списка пользователей», создавайте `users/page.tsx` внутри `src/app/`.

Когда AI говорит «создай компонент кнопки», создавайте `Button.tsx` внутри `src/components/`.

:::

::: tip Скоро появится

Этот туториал предоставляет skill `/project-init`, который автоматизирует весь процесс инициализации проекта.

**Что он умеет**:

1. **Проверка окружения**: автоматически проверяет версию Node.js и установку pnpm
2. **Умные рекомендации шаблонов**: подбирает подходящий tech stack по вашим потребностям (PRD, дизайн-макеты, идеи функций)
3. **Готовые шаблоны**:
   - Рекомендуемая конфигурация (только frontend)

   - Маркетинговый сайт/Landing Page
   - Админ-панель/Dashboard
   - Легковесное SPA

**Пример использования**:

Он проведёт вас через весь процесс: проверка окружения, анализ требований, выбор шаблона, установка зависимостей и настройка переменных окружения.

## Запустите проект

```bash
# Войти в каталог проекта (замените my-app на имя вашего проекта)
cd my-app

# Запустить dev-сервер
pnpm dev
```

Откройте браузер и зайдите на `http://localhost:3000`. Если видите страницу приветствия — проект создан успешно.

## FAQ

### Q: Какой шаблон использовать?

| Тип проекта | Рекомендуемый шаблон |
|----------|----------|
| Full-stack приложение | Next.js |
| Frontend SPA | Vite + React |
| Статический сайт | Astro |

Этот туториал использует **Next.js + TypeScript + Tailwind CSS** — это full-stack решение, отлично подходящее для AI-ассистированной разработки.

### Q: Я уже использую китайский путь — что делать?

В файловом менеджере сделайте следующее:

1. Удалите папку `node_modules`
2. Создайте новую папку с английским именем
3. Скопируйте остальные файлы в новую папку
4. Выполните `pnpm install` в новой папке

### Q: Можно ли просить AI создавать файлы по одному?

Не рекомендуется. Позволяя AI создавать файлы один за другим, легко получить пропущенные файлы, потраченное время и ошибки конфигурации. **Правильный подход**: сначала через scaffolding создайте стандартный проект, затем пусть AI модифицирует его в существующей структуре.

## Ключевая идея

**Используйте шаблоны вместо старта с нуля**.

| Способ | Результат |
|------|------|
| Создание через scaffolding | Стандартная структура, преднастроено, запуск одним кликом |
| Ручное создание | Легко пропустить файлы, ошибки конфигурации, потерянное время |

::: tip Рекомендации по именованию проекта
В имени проекта рекомендуется использовать строчные буквы и дефисы, избегая китайских иероглифов и пробелов (например, `my-todo-app`). Это помогает предотвратить проблемы совместимости с некоторыми инструментами.
:::

**Проверка после создания проекта**:

- [ ] Понимаю назначение каждой папки (`src/`, `public/`, `app/` и др.)
- [ ] Проект успешно запускается (`pnpm dev` проходит, браузер открывает `http://localhost:3000`)
