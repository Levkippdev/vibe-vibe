# 1.8 Localhost и порты

> **Прочитав этот раздел, вы получите:**
>
> - Понимание роли localhost и основ IP-адресов
> - Крепкое представление о портах и самых частых из них
> - Способность запускать/останавливать dev-сервер и разбирать конфликты портов

Создав проект, следующим шагом запускаем dev-сервер и смотрим на приложение в браузере.

## Базовые понятия

### Localhost

**localhost** — это «внутренний адрес» вашего компьютера, используемый для локальной разработки и тестирования.

| Адрес | Назначение |
|------|------|
| `localhost` | Локальное имя хоста, автоматически резолвится в 127.0.0.1 |
| `127.0.0.1` | Локальный loopback IP-адрес |
| `http://localhost:3000` | Сервис, работающий локально на порту 3000 |

Оба эквивалентны:

```bash
ping localhost      # Тот же эффект, что ниже
ping 127.0.0.1
```

::: tip localhost vs публичный адрес

| Dev-окружение | Production |
|----------|----------|
| `localhost:3000` | `https://example.com` |
| Доступ только у вас | Доступ есть у всех |
| Для разработки и отладки | Для рабочей эксплуатации |

:::

### Порт

**Порт** — это как дверь в доме. На один IP-адрес приходится 65535 портов, и на каждом может работать свой сервис.

Если IP-адрес — это **адрес здания**, то порт — **номер комнаты**:

| Порт | Сервис | Приложение |
|------|------|------|
| 3000 | Dev-сервер Next.js | `http://localhost:3000` |
| 5173 | Dev-сервер Vite | `http://localhost:5173` |
| 8000 | Python HTTP-сервер | `http://localhost:8000` |

**Частые порты разработки**:

| Порт | Назначение |
|------|------|
| 3000 | Next.js, Express |
| 5173 | Vite |
| 8000/8080 | Общие запасные порты |
| 80 | HTTP (production, можно опускать) |
| 443 | HTTPS (production, можно опускать) |

**Диапазоны номеров портов**:

- **0–1023**: системные порты, требуют прав администратора
- **1024–49151**: зарегистрированные порты, используются частыми сервисами
- **49152–65535**: динамические порты, временное использование

> 💡 **Упражнение**: кликните свободную комнату, чтобы запустить сервис; кликните занятую — чтобы вызвать ошибку EADDRINUSE; переключайте режимы dev/production и смотрите различия архитектуры
>
> 🎯 **Ключевая идея**: порт — это «номер комнаты», и на одном порту может работать только один сервис

## Запуск dev-сервера

```bash
# Войти в каталог проекта (замените my-app на имя вашего проекта)
cd my-app

# Установить зависимости (только при первом запуске)
pnpm install

# Запустить dev-сервер
pnpm dev
```

::: tip Почему сначала нужно установить зависимости?

`pnpm install` скачивает все пакеты кода (зависимости), нужные проекту. Без этого шага проект не запустится. Это как сборка мебели: сначала нужно убедиться, что все детали на месте.

:::

После запуска вы увидите примерно такой вывод:

```
▲ Next.js 16.1.4
- Local:        http://localhost:3000
- Network:      http://192.168.1.100:3000

✓ Ready in 1.2s
```

Откройте браузер и зайдите на `http://localhost:3000`.

::: tip Когда нужно выполнять pnpm dev?

Запуск нужен **каждый раз, когда приступаете к работе**:

- При первом открытии проекта
- Когда хотите увидеть результат после правки кода (сервер обновляется сам, перезапуск не нужен)
- Когда хотите продолжить работу после остановки сервера

Запущенный сервер может работать, пока вы не закончите.

:::

::: tip Зачем нужен адрес Network?

По адресу Local можете зайти только вы. Адрес Network позволяет другим устройствам в той же локальной сети (например, вашему телефону) открывать страницу — это удобно для тестов на мобильных.

:::

## Остановка dev-сервера

Нажмите `Ctrl + C` в terminal, чтобы остановить.

| Система | Действие |
|------|------|
| Windows / Mac / Linux | Нажать `Ctrl + C` |

::: warning Страница перестаёт работать после остановки сервера

Когда вы закрываете terminal или останавливаете сервер через `Ctrl+C`, страница на `localhost:3000` перестаёт быть доступной.

**Это нормально**: dev-сервер отдаёт контент, только пока работает. В следующий раз просто выполните `pnpm dev` заново.

:::

## Разбор конфликтов портов

Если при запуске вы видите сообщение, что порт уже занят:

```
Error: listen EADDRINUSE: address already in use :::3000
```

**Самое простое решение — попросить AI**: отправьте ему сообщение об ошибке, и он поможет разобраться.

Также можно вручную переключиться на другой порт:

```bash
# Next.js: запуск на указанном порту
pnpm dev -- -p 3001
```

::: tip Автоматическая обработка конфликтов портов

Современные инструменты разработки (например, Next.js 14+) автоматически определяют конфликт портов. Если 3000 занят, они автоматически попробуют 3001, 3002 и так далее.

**Но если вы видите ошибку EADDRINUSE** — значит, автодетект не сработал, и можно просто попросить AI помочь.

:::

::: tip Команды, которые может использовать AI

Если вам интересно, какими командами AI решил бы это, смотрите ниже:

**Mac / Linux**:

```bash
lsof -ti:3000 | xargs kill -9
```

Одна команда делает всё: находит процесс, использующий порт 3000, и завершает его.

**Windows**:

```powershell
netstat -ano | findstr :3000
```

Сначала узнайте PID процесса, занимающего порт, затем:

```powershell
taskkill /PID 12345 /F
```

Замените `12345` на реальный PID.

:::

## Частые вопросы

### Q: Почему после запуска сервера браузер автоматически открывает localhost?

Это удобная функция инструментов разработки. Vercel и Vite умеют определять старт сервера и автоматически открывать браузер.

### Q: Почему страница не меняется после правки кода?

Dev-сервер поддерживает **hot reload** — он обновляется автоматически после сохранения файла. Если этого не происходит:

- Проверьте, работает ли сервер нормально
- Попробуйте вручную обновить браузер (F5)

### Q: Можно ли зайти на localhost из локальной сети?

Нет. `localhost` доступен только на самой машине. Для доступа по LAN нужно использовать локальный сетевой IP машины:

```bash
# Посмотреть свой локальный IP
ipconfig        # Windows
ifconfig        # Mac/Linux

# Доступ по LAN
http://192.168.1.100:3000
```

### Q: Порт 3000 используется и в production?

Может быть, но пользователям обычно не дают прямой доступ к порту 3000.

**Типичная production-архитектура**:

```mermaid
graph LR
    A[Браузер пользователя] --> B[https://example.com<br/>Порт 80/443]
    B --> C[Nginx / OpenResty<br/>Реверс-прокси]
    C --> D[Ваше приложение<br/>Порт 3000]

    style A fill:#e3f2fd
    style C fill:#fff3e0
    style D fill:#f3e5f5
```

Когда пользователь заходит на `https://example.com`, запрос сначала попадает в Nginx (слушающий порты 80/443), а затем Nginx форвардит его в ваше приложение (порт 3000).

**Конечно, можно дать пользователям и прямой доступ по IP + порт**:

```
http://IP-вашего-сервера:3000
```

Но это не очень удобно и открывает номер порта наружу. Рекомендуется использовать Nginx как реверс-прокси, чтобы пользователи запоминали только доменное имя.

## Ключевая идея

**Localhost — фундамент локальной разработки**.

- ✅ localhost = 127.0.0.1, оба указывают на локальный компьютер
- ✅ Порты различают сервисы — на одном компьютере может работать несколько сервисов
- ✅ Для разработки — localhost, для production — доменное имя
- ✅ Один порт может использовать только один процесс за раз
- ✅ `Ctrl + C` останавливает сервер
