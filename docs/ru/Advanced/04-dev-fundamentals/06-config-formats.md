## Что такое форматы структурированных данных

Форматы структурированных данных — способы представления данных строгими правилами организации. Они позволяют компьютерам точно парсить и понимать данные.

В сравнении с естественным языком, структурированные форматы:

- Консистентны по формату, без двусмысленности
- Легко парсятся и генерируются программами
- Универсальны между языками и платформами
- Легко и точно понимаются AI

Чтобы понять ценность структурированных данных, полезно взглянуть на эволюцию языков программирования. Ранние языки были ближе к машине: программистам приходилось работать с адресами памяти и бинарными данными напрямую. С появлением высокоуровневых языков данные абстрагировались в концепции переменных, объектов и массивов — программисты могли описывать данные более естественными способами. JSON и YAML представляют высший уровень этой абстракции: это не синтаксис одного конкретного языка, а «лингва франка», которую понимают все современные языки. Используете вы Python-словари, JavaScript-объекты или Go-структуры — всё это в итоге без потерь конвертируется в JSON и парсится другими языками. Эта универсальность — фундамент интероперабельности современной софт-экосистемы.

::: tip Как AI предпочитает читать

В сравнении со свободным естественным языком, чётко структурированные форматы — та «документация», которую AI любит больше всего. Пишя требования или конфигурацию в JSON/YAML, вы даёте AI понять их куда точнее.

:::

## Формат JSON

**JSON (JavaScript Object Notation)** — самый частый формат обмена данными.

### Правила синтаксиса

```json
{
  "name": "John",
  "age": 25,
  "email": "john@example.com",
  "address": {
    "city": "Beijing",
    "district": "Chaoyang"
  },
  "hobbies": ["reading", "swimming", "programming"]
}
```

**Обзор правил**:

- Фигурные скобки `{}` представляют объекты
- Квадратные скобки `[]` представляют массивы
- Данные организованы парами «ключ: значение»
- Ключи обязаны быть в двойных кавычках
- Пары ключ-значение разделяются запятыми

### Типы данных

| Тип | Пример | Описание |
|------|------|------|
| Строка | `"hello"` | В двойных кавычках |
| Число | `123`, `3.14` | Целое или число с плавающей точкой |
| Булево | `true`, `false` | Истина/ложь |
| Массив | `[1, 2, 3]` | Упорядоченный список данных |
| Объект | `{"key": "value"}` | Коллекция пар ключ-значение |
| null | `null` | Пустое значение |

### Преимущества JSON

| Преимущество | Описание |
|------|------|
| **Универсальность** | Поддерживается всеми языками программирования |
| **Читаемость** | Легко читается людьми |
| **Компактность** | Лаконичный формат без лишнего места |
| **Web-стандарт** | Стандартный формат HTTP API |

::: tip JSON — лингва франка цифровой эпохи

Пишете ли вы backend на Python, frontend на JavaScript или код пишет AI — все используют JSON для передачи данных. Без JSON у каждого языка был бы свой «диалект»-формат — как у разных регионов когда-то были свои языки, что сильно усложняло общение.

:::

## Формат YAML

**YAML (YAML Ain't Markup Language)** — более дружелюбный к человеку конфиг-формат.

### Правила синтаксиса

```yaml
# Информация юзера
name: John
age: 25
email: john@example.com

# Информация адреса
address:
  city: Beijing
  district: Chaoyang

# Хобби
hobbies:
  - reading
  - swimming
  - programming
```

**Обзор правил**:

- Иерархия выражается отступами (только пробелы, не табы)
- Ключи и значения разделяются двоеточием
- Пункты массивов — дефис `-`
- `#` в начале строки — комментарий

### Преимущества YAML

| Преимущество | Описание |
|------|------|
| **Более читаемый** | Ощущение естественности, как чек-лист |
| **Поддержка комментариев** | Можно добавлять пояснения |
| **Лаконичность** | Без скобок, кавычек и запятых |
| **Отличен для конфигурации** | Часто используется для конфиг-файлов |

::: tip YAML vs JSON

YAML — как «чек-лист», JSON — как «таблица». YAML легче для написания конфигов, JSON — стандартнее для передачи данных.

:::

## CSV: плоский формат файлов

Говоря о структурированных данных, **CSV (Comma-Separated Values)** — один из простейших форматов. Он хранит табличные данные как простой текст: каждая строка — запись, поля разделены запятыми.

**Пример CSV**:

```csv
name,email,age
John,john@example.com,25
Jane,jane@example.com,30
```

**Характеристики CSV**:

- **Простота**: открывается любым текстовым редактором
- **Высокая совместимость**: импортируется напрямую в Excel и Google Sheets
- **Малый размер**: без лишней форматной разметки

**Ограничения CSV**:

- Только двумерные таблицы (строки и колонки)
- Нет вложенных структур
- Нет типов данных (всё — строки)
- Сложные отношения — плохо

**CSV vs JSON/YAML**:

| Характеристика | CSV | JSON/YAML |
|------|-----|-----------|
| Структура | Двумерная таблица | Произвольная вложенность |
| Типы данных | Нет | Строки, числа, булевы и т.д. |
| Моделирование связей | Слабое | Сильное |
| Сценарии | Простой экспорт, обмен таблицами | Конфиги, API-данные, сложные структуры |

CSV отлично подходит для экспорта данных из таблиц или обмена простыми данными с коллегами на Excel. Но для Web-разработки JSON и YAML лучше — они представляют более сложные структуры данных.

## Реальные примеры

### JSON: данные юзера

```json
{
  "id": "user_123",
  "name": "John",
  "email": "john@example.com",
  "avatar": "https://example.com/avatar.jpg",
  "location": {
    "country": "China",
    "province": "Beijing",
    "city": "Beijing"
  },
  "birthday": "1990-01-15",
  "phone": "+86 138 0000 0000"
}
```

### YAML: конфигурация приложения

```yaml
# Конфигурация приложения
app:
  name: "My Blog"
  version: "1.0.0"
  port: 3000

# Конфигурация базы
database:
  host: "localhost"
  port: 5432
  name: "blog_db"
  user: "admin"
  password: "${DB_PASSWORD}"  # Ссылка на переменную окружения

# Фичефлаги
features:
  enable_comments: true
  enable_analytics: false
```

### JSON: ответ API

```json
{
  "success": true,
  "data": {
    "posts": [
      {
        "id": "1",
        "title": "Первая статья",
        "author": "John"
      },
      {
        "id": "2",
        "title": "Вторая статья",
        "author": "Jane"
      }
    ],
    "total": 2,
    "page": 1
  }
}
```

### YAML: конфигурация CI/CD

```yaml
# Конфигурация GitHub Actions
name: Deploy
on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Install dependencies
        run: pnpm install
      - name: Build
        run: pnpm build
      - name: Deploy
        run: pnpm deploy
```

## Применение в разработке

### package.json (JSON)

Конфиг-файл Node.js-проектов, определяющий зависимости и скрипты проекта:

```json
{
  "name": "my-project",
```

## Частые вопросы

### Q1: А комментарии в JSON?

Стандарт JSON не поддерживает комментарии. Если нужны комментарии — используйте JSONC (JSON with Comments) или переходите на YAML.

### Q2: Отступы YAML — пробелы или табы?

Только пробелы, никогда табы. Обычно один уровень отступа — 2 пробела.

### Q3: Как выбирать между JSON и YAML?

- Передача данных, ответы API: JSON
- Конфиг-файлы: предпочесть YAML
- Нужны комментарии: YAML
- Web API: JSON

### Q4: Что если я ошибся в формате?

Большинство редакторов дают проверку синтаксиса. Попросить AI помочь — тоже хороший вариант: он укажет точное место ошибки и даст правильный формат.
