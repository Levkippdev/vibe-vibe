# 6.0 Получите свою базу данных

> **Цель раздела**: зарегистрироваться на бесплатной облачной PostgreSQL-базе, получить connection string и убедиться, что подключение работает.

Во введении вы уже узнали основы баз данных. Пора получить собственную.

## Зачем облачная база данных

Вы можете спросить: а нельзя ли просто установить PostgreSQL на свой компьютер? Конечно можно, но опытные разработчики обычно не рекомендуют это новичкам:

- Локальная установка и настройка муторны и легко ломаются
- При деплое в онлайне всё равно пришлось бы мигрировать данные заново
- **Free tier** облачной базы более чем достаточен для личных проектов

Выгоды облачной базы просты: зарегистрировались — сразу пользуетесь, автоматические бэкапы, доступ отовсюду. База, к которой вы подключаетесь, кодя дома, — та же, к которой подключится Vercel после деплоя, что избавляет от головной боли несовпадения окружений.

## Вариант 1: Neon (рекомендуется)

**Neon** — serverless-платформа баз, сфокусированная на PostgreSQL: не нужно самостоятельно устанавливать базу или управлять серверами. Neon берёт всё это на себя — вы просто подключаетесь и пользуетесь. Free tier щедрый, cold starts быстрые (cold start — задержка «прогрева» при первом обращении к базе после простоя), что отлично подходит личным проектам.

![image-20260222223036476](/images/Advanced/image-20260222223036476.jpg)

### Шаги регистрации

**Шаг 1: Откройте сайт Neon**

Откройте [neon.tech](https://neon.tech) и кликните **Log In** в правом верхнем углу. Рекомендуется входить через GitHub-аккаунт для one-click авторизации.

![image-20260222223100463](/images/Advanced/image-20260222223100463.png)

**Шаг 2: Создайте проект**

![image-20260222223148855](/images/Advanced/image-20260222223148855.png)

После входа создайте первый проект. Заполните следующую информацию:

- **Project Name**: что угодно, например `my-first-app`
- **Region**: выберите ближайший регион. Для юзеров в Китае рекомендуется **Сингапур** — минимальная задержка
- **Database Name**: оставьте дефолтное `neondb`

![image-20260222223211499](/images/Advanced/image-20260222223211499.png)

**Шаг 3: Получите connection string**

После создания проекта Neon напрямую покажет ваш **Connection String**. Он выглядит так:

```
postgresql://username:password@ep-xxx-xxx-123.us-east-2.aws.neon.tech/neondb?sslmode=require
```

![image-20260222223303602](/images/Advanced/image-20260222223303602.png)

::: warning Храните connection string в безопасности
Connection string содержит имя юзера и пароль — это по сути ключ от вашей базы. **Никогда** не коммитьте его в GitHub и не отправляйте никому. Храните его в файле `.env` проекта:

```bash
DATABASE_URL="postgresql://username:password@ep-xxx.neon.tech/neondb?sslmode=require"
```

:::

### Что входит в free tier Neon

| Ресурс | Бесплатный лимит |
|------|---------|
| Хранилище | 512 MB |
| Compute-время | 100 compute-часов на проект |
| Количество проектов | 100  |
| Количество веток | 10 |

Для обучения и личных проектов этих лимитов более чем достаточно.

## Вариант 2: Supabase

**Supabase** не только даёт базу PostgreSQL, но и идёт с аутентификацией, хранилищем, real-time подписками и др. Если нужен all-in-one backend-сервис — это основательный выбор.

### Шаги регистрации

**Шаг 1: Откройте сайт Supabase**

Откройте [supabase.com](https://supabase.com) и кликните **Start your project**, затем войдите через GitHub.

![image-20260222223411365](/images/Advanced/image-20260222223411365.png)

**Шаг 2: Создайте организацию и проект**

![image-20260222223437677](/images/Advanced/image-20260222223437677.png)

- **Organization**: введите имя организации

- **Project Name**: например `my-first-app`

- **Database Password**: задайте сильный пароль и **запишите его**

- **Region**: выберите **Southeast Asia (Singapore)**

  ![image-20260222223509375](/images/Advanced/image-20260222223509375.png)



**Шаг 3: Получите connection string**

После создания проекта откройте homepage и кликните **Connect** сверху:

![image-20260222223646279](/images/Advanced/image-20260222223646279.png)

Для Method выберите Transaction pooler (это конкретная реализация упомянутого ранее «пула соединений» — просто выбирайте его); если есть время, можно дополнительно настроить MCP.

![image-20260222224026943](/images/Advanced/image-20260222224026943.png)

```
postgresql://postgres.[project-ref]:[YOUR-PASSWORD]@aws-0-ap-southeast-1.pooler.supabase.com:6543/postgres
```



### Что входит в free tier Supabase

| Ресурс | Бесплатный лимит |
|------|---------|
| Хранилище базы | 500 MB |
| Файловое хранилище | 1 GB |
| Трафик | 5 GB / месяц |
| Количество проектов | 2 |
| Edge Functions | 500 000 вызовов / месяц |

::: tip Как выбирать между Neon и Supabase?

- **Нужна только база** → выбирайте Neon: сфокусированный, легковесный, щедрые free-лимиты
- **Нужен полный пакет** (база + auth + storage + real-time) → выбирайте Supabase
- Этот туториал рекомендует **Neon**, потому что мы используем стандартный PostgreSQL + независимое auth-решение (Better Auth), не привязываясь к платформе
:::

## Проверьте подключение

Получив connection string, как убедиться, что он реально работает?

### Метод 1: Пусть AI проверит за вас

Простейший способ — сказать AI напрямую:

> «Используй DATABASE_URL из моего .env, чтобы протестировать подключение к базе и подтвердить, что оно работает»

AI напишет простой тест-скрипт и скажет, успешно ли подключение после запуска.

### Метод 2: Визуальная проверка через Drizzle Studio

Если ваш проект уже настроен с Drizzle ORM, запустите:

```bash
pnpm drizzle-kit studio
```

В браузере откроется визуальный интерфейс, где можно напрямую видеть таблицы и данные вашей базы. Если он открылся — подключение работает.

![image-20260222230115049](/images/Advanced/image-20260222230115049.png)

### Метод 3: Проверка прямо в консоли платформы

Самый интуитивный способ — открыть web-консоль платформы базы и листать данные как таблицу. В разработке неплохо держать консоль открытой, чтобы в любой момент проверить, корректно ли записались данные.

**Neon Console**: после входа в проект кликните **Tables** слева для просмотра табличных данных. Можно также исполнять запросы напрямую в **SQL Editor**.

![image-20260222230548275](/images/Advanced/image-20260222230548275.png)

**Supabase Table Editor**: после входа в проект кликните **Table Editor** слева, чтобы листать, фильтровать и редактировать табличные данные как в таблице.

![image-20260222230528345](/images/Advanced/image-20260222230528345.png)

### Частые проблемы подключения

| Сообщение об ошибке | Причина | Решение |
|---------|------|---------|
| `Invalid URL` | Неверный формат connection string | Проверьте лишние пробелы и соответствие кавычек |
| `password authentication failed` | Неверный пароль | Сбросьте пароль на платформе и обновите `.env` |
| `connection refused` | Сетевое подключение провалилось | Проверьте, нужен ли `?sslmode=require` (SSL шифрует коммуникацию между вами и базой, предотвращая перехват пароля в пути) |
| `too many connections` | Превышен лимит соединений | Используйте адрес connection pooler'а |

::: tip Что такое пул соединений?
Каждое соединение с базой потребляет 1–3 МБ памяти, а общее число соединений ограничено (обычно от десятков до пары сотен). Если приложение создаёт новое соединение на каждый запрос и закрывает его сразу после использования, доступные соединения быстро исчерпаются, и все последующие юзеры начнут получать ошибки.

**Connection Pooler** — как «посредник по соединениям»: он заранее создаёт пачку соединений с базой. Приложению нужно — берёт одно; закончило — возвращает, и следующий запрос переиспользует то же соединение. Так, 100 конкурентных юзеров могут обойтись 10 реальными соединениями с базой.

И Neon, и Supabase предоставляют адреса pooler'ов (обычно на других портах — например, прямые соединения Supabase используют 5432, а pooler — 6543). **При деплое в production обязательно используйте адрес pooler'а**, иначе упрётесь в `too many connections` с первым же ростом трафика.
:::

## Настройте connection string в проекте

В корневом каталоге вашего Next.js-проекта создайте или отредактируйте файл `.env`:

```bash
# Подключение к базе (замените своим)
DATABASE_URL="postgresql://username:password@host/dbname?sslmode=require"
```

Убедитесь, что `.gitignore` включает `.env` (в Next.js-проектах он включён по умолчанию).

Затем скажите AI:

> «В проекте настроен DATABASE_URL. Пожалуйста, инициализируй подключение к базе с помощью Drizzle ORM»

AI поможет создать файлы вроде `src/db/index.ts` и наладить подключение к базе.
