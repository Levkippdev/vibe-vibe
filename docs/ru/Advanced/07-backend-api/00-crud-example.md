# 7.0 Соберите и запустите ваше первое full-stack приложение

> **Цель раздела**: пусть AI сгенерирует для вас полное CRUD-приложение, запустите его и убедитесь, что данные корректны.

В главе 6 вы настроили базу данных, а во введении узнали концепцию API. Пора соединить их — построив самое классическое приложение из всех: **Todo-приложение**.

## Full-stack поток данных: поймите с одного взгляда

Прежде чем начать, поймите, как текут данные:

```
Юзер кликает «Добавить» → Frontend отправляет запрос → Backend API принимает → Drizzle пишет в базу
                                                                ↓
Юзер видит новые данные ← Frontend рендерит ответ ← Backend возвращает результат ← База подтверждает
```

Это ключевой цикл full-stack приложения. Все четыре CRUD-операции следуют тем же путём.

## Поручите AI создать проект

Этот код не нужно писать руками. Просто скажите AI:

> «Помоги мне создать Todo-приложение на Next.js + Drizzle ORM + PostgreSQL. Нужна полная CRUD-функциональность: добавление задач, просмотр списка, отметка выполненными и удаление. Для подключения к базе используй DATABASE_URL из .env».

AI поможет сгенерировать такую файловую структуру:

```
src/
├── db/
│   ├── index.ts          # Подключение к базе
│   └── schema.ts         # Определение схемы таблиц
├── app/
│   ├── api/todos/
│   │   └── route.ts      # API-роут (обрабатывает CRUD-запросы)
│   └── page.tsx           # Страница frontend (отображение и интеракции)
```

## Ревью работы AI

AI сгенерировал три типа файлов. Не нужно понимать каждую строку — но нужно знать, за что отвечает каждый файл, чтобы при сбое понимать, какой файл просить AI починить.

### 1. Схема базы (`schema.ts`)

Этот файл определяет, «как выглядят данные»: какие поля у Todo и какого типа каждое поле. Это чертёж базы.

<details>
<summary>Любопытно, как это выглядит? Развернуть; смело пропускайте</summary>

```typescript
// src/db/schema.ts
export const todos = pgTable('todos', {
  id: serial('id').primaryKey(),
  title: text('title').notNull(),
  completed: boolean('completed').default(false),
  createdAt: timestamp('created_at').defaultNow(),
})
```

Сверьте с изученным в главе 6: `id` — primary key, `title` не бывает пустым, `completed` по умолчанию `false`, а `createdAt` автоматически записывает время создания.

</details>

### 2. API-роут (`route.ts`)

Этот файл — «интерфейс backend»: сюда отправляет запросы frontend, и он взаимодействует с базой. `POST` соответствует «Create», `GET` — «Read» — это RESTful-дизайн из введения.

<details>
<summary>Любопытно, как это выглядит? Развернуть; смело пропускайте</summary>

```typescript
// src/app/api/todos/route.ts

// C - Create: Добавить новую задачу
export async function POST(request: Request) {
  const { title } = await request.json()
  const newTodo = await db.insert(todos).values({ title }).returning()
  return Response.json(newTodo[0])
}

// R - Read: Получить все задачи
export async function GET() {
  const allTodos = await db.select().from(todos).orderBy(todos.createdAt)
  return Response.json(allTodos)
}
```

</details>

### 3. Страница frontend (`page.tsx`)

Этот файл — интерфейс для юзеров: поле ввода, список, чекбоксы и кнопка удаления. Он оперирует данными, вызывая API выше:

- При загрузке страницы — `GET /api/todos` для получения списка
- Когда юзер вводит название и кликает «Добавить» — `POST /api/todos`
- Когда юзер кликает чекбокс — `PATCH /api/todos/[id]` для обновления статуса
- Когда юзер кликает удаление — `DELETE /api/todos/[id]`

## Запустите

Теперь запустим по-настоящему. Если первый раз не заработает — это абсолютно нормально: может, нет переменной окружения, таблица не запушена, порт занят. Всё это часть опыта новичка. Просто вставьте ошибку в AI.

**Шаг 1: Запушите схему в базу**

```bash
pnpm drizzle-kit push
```

Эта команда синхронизирует схему таблиц, определённую в `schema.ts`, с вашей облачной базой.

**Шаг 2: Запустите dev-сервер**

```bash
pnpm dev
```

Откройте `http://localhost:3000` — вы должны увидеть пустой список задач.

**Шаг 3: Попробуйте CRUD**

| Операция | Что делаете вы | Что происходит за кадром |
|------|---------|--------------|
| Добавить | Вводите «Изучить базы» и кликаете Добавить | `POST /api/todos` → База вставляет строку |
| Посмотреть | Страница автоматически обновляет список | `GET /api/todos` → База запрашивает все строки |
| Завершить | Кликаете чекбокс | `PATCH /api/todos/1` → База обновляет поле `completed` |
| Удалить | Кликаете кнопку удаления | `DELETE /api/todos/1` → База удаляет строку |

## Проверка через Drizzle Studio

Хотите своими глазами увидеть, что происходит в базе?

```bash
pnpm drizzle-kit studio
```

Когда откроется, вы увидите каждую строку таблицы `todos` — и она будет точно соответствовать тому, что вы делали на странице.

Это одно из ваших ключевых навыков как владельца продукта: не чтение кода, а верификация результатов. Данные в базе корректны? Формат API-ответа корректен? Страница показывает правильный контент? Если вы можете проверить эти три вещи — вы можете уверенно поручать AI писать backend.

## Частые вопросы

**Q: Список не обновляется после добавления?**

Скажите AI: «Автоматически обновляй список после добавления задачи. Не хочу вручную refresh'ить страницу». AI рефетчит данные после успешного POST-запроса.

**Q: Удаление возвращает 404?**

Проверьте, корректен ли путь файла API-роута. Динамические роуты Next.js требуют папки `[id]`: `app/api/todos/[id]/route.ts`.

**Q: В базе нет таблицы?**

Убедитесь, что запустили `pnpm drizzle-kit push`. Если ошибка — проверьте корректность `DATABASE_URL` в `.env`.

## Чему учит этот пример

Вы только что завершили **минимальное, но полное full-stack приложение**. Оно включает:

- **Frontend**: UI, обработка событий, вызовы API
- **Backend**: API-роуты, обработка запросов, валидация данных
- **База**: схема таблиц, CRUD-операции, персистентность данных

Какое бы приложение вы ни строили дальше — блог, e-commerce, социальное — логика под капотом всегда сводится к этим четырём буквам: **CRUD**. Разница лишь в том, что схема усложняется, бизнес-логика растёт, а UI становится навороченнее.
