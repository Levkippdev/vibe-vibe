# Глава 8: Безопасность и аутентификация юзеров

![img](/images/Advanced/mll04qyy-61b0d268ae22452a.jpg)

## Предисловие

Backend «личного Douban» Сяомина заработал. CRUD работал исправно, API обзавелись валидацией и пагинацией. Друзья несколько дней тестировали — все сказали: неплохо. Он решил, что почти готово, — пора запушить код на GitHub: частично как бэкап, частично чтобы показать друзьям, что он построил.

`git add .`, `git commit`, `git push`. Всё одним плавным движением.

Через десять минут — письмо. От OpenAI:

> «Ваш аккаунт за последние 10 минут израсходовал $127.43 на использование API».

Сяомин окаменел. В тот день он вообще не пользовался AI-фичами. Он открыл дашборд OpenAI — логи API скроллились как безумные: десятки вызовов в секунду, все из незнакомых запросов. В панике он бросился проверять GitHub-репозиторий — и сердце упало: файл `.env` лежал на виду, с `OPENAI_API_KEY` внутри — для всех желающих.

Чего он не знал: в интернете тысячи автоматических ботов сканируют каждый коммит GitHub 24/7. Им плевать, хороший у вас код или плохой. Они ищут одно: секреты. В среднем проходит всего **5 минут** от появления секрета в публичном репозитории до его злоупотребления. Ключ Сяомина был скомпрометирован в момент `git push`.

Он быстро удалил `.env` с GitHub и запушил снова. Но ветеран покачал головой: «Поздно. Git записывает историю каждого коммита. Ты удалил только последнюю версию. Любой, кто посмотрит историю коммитов, всё ещё найдёт ключ там».

Тогда Сяомин осознал серьёзность. Весь вечер он ротировал каждый секрет, вычищал историю Git и переконфигурировал переменные окружения. Счёт на $127 — меньшее из зол. По-настоящему испугало другое: что если бы утёк не ключ OpenAI, а пароль базы? email юзеров, хэши паролей, персональные данные — всё наружу.

Наблюдая, как он заканчивает всю эту уборку, ветеран сказал одну вещь: «Каким бы хорошим ни был твой код, если утекут секреты — ничего не имеет значения. Безопасность — не то, что посыпают сверху после готовности фич. Это то, о чём думают с самой первой строки кода».

---

Тот опыт преподал Сяомину урок. Он начал осознавать: между приложением, которое «работает», и приложением, которое действительно «защищено», долгий путь.

Начиная с дорого обошедшегося Сяомину урока, эта глава поможет вам построить полное security-мышление:

- **Как управлять секретами** — переменные окружения, `.gitignore` и облачная конфигурация, чтобы секреты никогда не появлялись в коде
- **Как идентифицировать юзеров** — принципы регистрации и логина и почему стоит использовать зрелую auth-библиотеку, а не писать свою
- **Как защищать роуты** — Middleware, CORS и контроль доступа, чтобы каждый запрос проверялся
- **Как разбираться с проблемами** — гайд по troubleshooting от «конфиг не применился» до «секрет утёк»
- **Как обороняться от глубоких угроз** — SQL-инъекции, XSS, CSRF и security-специфика AI-приложений

Всё это не нужно учить разом. В 8.0 вы сначала заставите юзер-систему работать, чтобы построить интуицию; в последующих разделах сможете возвращаться и смотреть, когда столкнётесь с конкретной проблемой.
