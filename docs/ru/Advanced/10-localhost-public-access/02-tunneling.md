# 10.2 Сетевое туннелирование: пусть друг быстро глянет

> **Цель раздела**: понять, как работает сетевое туннелирование, через Cloudflare Tunnel сгенерировать временную публичную ссылку и отправить её другу.

## Зачем нужно сетевое туннелирование

Друг Сяомина в другом городе, они не в одной локальной сети. Формальный деплой потребует Git, конфигурации платформы и доменного имени — а он просто хочет, чтобы друг быстро глянул, как работает фича рейтингов.

Ветеран сказал: «Есть временное решение — сетевое туннелирование. Без деплоя, без домена, одна команда — и публичная ссылка готова».

## Как работает туннель

В своей основе сетевое туннелирование создаёт **туннель** между вашим компьютером и публичным сервером.

<TunnelFlow />

Друг заходит по временному адресу на публичном сервере, сервер пересылает запрос на ваш компьютер, затем возвращает ответ вашего компьютера обратно другу. Другу всё это время не нужно знать ваш IP-адрес, а вам — иметь публичный IP.

Бытовая аналогия: видеозвонок WeChat. Вы и друг не в одной сети, но серверы WeChat релеят между вами аудио- и видеоданные. Сетевое туннелирование похоже, только релеятся web-запросы.

Ключевая разница: туннель устанавливаете вы проактивно. Ваш компьютер инициирует соединение к публичному серверу (исходящее), а не публичный сервер пытается достучаться до вашего компьютера (входящее). Поскольку исходящие соединения не блокируются NAT и firewall, туннель обходит проблему «у домашнего широкополосного доступа нет публичного IP».

## Cloudflare Tunnel (рекомендуется)

Cloudflare Tunnel — простейший вариант: бесплатно, без регистрации, без лимитов трафика.

### Установка

Скажите Claude Code:

> «Помоги мне установить инструмент командной строки cloudflared».

Или установите вручную:

::: code-group

```bash [Windows]
winget install cloudflare.cloudflared
```

```bash [macOS]
brew install cloudflared
```

```bash [Linux (Debian/Ubuntu)]
curl -L https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb -o cloudflared.deb
sudo dpkg -i cloudflared.deb
```

:::

### Запуск туннеля

Убедитесь, что проект работает локально (например, `pnpm dev` на порту 3000), затем **откройте другой терминал**:

```bash
cloudflared tunnel --url http://localhost:3000
```

Терминал выдаст временную ссылку:

```
https://random-words-here.trycloudflare.com
```

Отправьте её другу — и он увидит ваш проект.

::: tip Ссылка каждый раз другая
В бесплатном режиме каждый запуск cloudflared генерирует новую случайную ссылку. Закрыли терминал (Ctrl+C) — ссылка немедленно перестаёт работать. Это задумано: временное решение должно выглядеть временным.
:::

### Пусть AI сделает всё одной командой

Не хотите запоминать команды — просто скажите Claude Code:

> «Помоги через Cloudflare Tunnel выставить мой локальный порт 3000 в публичный интернет и сгенерировать временную ссылку, которую я отправлю другу».

Claude Code проверит, установлен ли cloudflared, поставит при необходимости и запустит туннель.

### Частые вопросы

**Ссылка сгенерирована, но друг не может открыть?** Убедитесь, что dev-сервер действительно запущен. cloudflared только пересылает запросы: если локальный сервис не работает, друг увидит просто страницу ошибки.

**Терминал показывает ошибку соединения?** Проверьте номер порта. Если проект работает на 5173 (дефолт Vite), а не 3000, команда должна быть `cloudflared tunnel --url http://localhost:5173`.

**Очень медленно?** Это норма. Запрос идёт от устройства друга до сервера Cloudflare, потом до вашего компьютера и обратно тем же путём. Задержка зависит от качества сети между вами и сервером Cloudflare. Если вы в Китае и скорость невыносима — рассмотрите cpolar.

## Альтернативные варианты

Cloudflare Tunnel достаточно хорош для большинства сценариев. При особых требованиях есть две альтернативы:

**ngrok**: проверенный временем инструмент, требует регистрации бесплатного аккаунта. Преимущество — встроенная web-панель отладки (`http://localhost:4040`), где можно инспектировать все запросы и ответы, проходящие через туннель, — очень удобно для дебага. В бесплатном тарифе лимиты соединений, а посетители увидят предупреждение ngrok. Официальный сайт: [ngrok.com](https://ngrok.com)

**cpolar**: сервис с серверами в Китае. Если и вы, и друг в Китае, он заметно быстрее Cloudflare и ngrok. Требует аккаунт. Официальный сайт: [cpolar.com](https://www.cpolar.com)

| Инструмент | Регистрация | Скорость в Китае | Особенности |
|------|------------|---------|------|
| Cloudflare Tunnel | Нет | Средняя | Простейший, бесплатно и без лимитов |
| ngrok | Да | Средняя | Отличная дебаг-панель |
| cpolar | Да | Быстрая | Оптимизирован для Китая |

Что выбрать? Без особых требований — Cloudflare Tunnel. Нужна дебаг-панель — ngrok. Вы в Китае и скорость — узкое место — cpolar.

::: tip Учить все не нужно
Ключевой воркфлоу всех трёх инструментов почти одинаков: установить → запустить одной командой → получить ссылку → отправить другу. Возьмите один и освойте. Если сомневаетесь — Cloudflare Tunnel: без регистрации, без конфигурации, бесплатно и без лимитов.
:::

## Security-замечания

В момент открытия туннеля ваш компьютер временно выставлен в публичный интернет. Даже если это временно, несколько вещей обязательно нужно держать в голове:

**Закрывайте сразу по окончании**. Ctrl+C останавливает cloudflared — туннель отрезается. Не оставляйте туннель на ночь и не уходите из дома с открытым туннелем.

**Не выставляйте порты, которые выставлять не нужно**. Туннель должен указывать только на порт вашего web-приложения (например, 3000). Порты баз (5432, 3306), админ-панели, дебаг-инструменты — никогда не должны выставляться через туннель.

**Убедитесь, что включена аутентификация**. Если в проекте есть логин (результат главы 8), убедитесь, что он включён. Не отключайте логин «на минуточку, другу же просто глянуть» — ссылка туннеля публична, и любой её получивший сможет зайти.

**Не передавайте чувствительные данные через туннель**. Туннели подходят для демонстрации UI и фич, а не для обработки реальных данных юзеров или паролей.

::: warning Правило одной фразы
Туннель — это временная дырка, просверленная в стене. Друг досмотрел — сразу же замажьте дырку.
:::

### Security-чек-лист

Перед открытием туннеля быстро проверьте:

- [ ] Включена ли фича логина проекта (результат главы 8)
- [ ] Есть ли в `.env` чувствительная информация (API-ключи, пароли баз) — через туннель она не утечёт, но перепроверить никогда не мешает
- [ ] Указывает ли туннель только на порт web-приложения, не выставляя других сервисов
- [ ] Будет ли туннель закрыт сразу после демонстрации

## От временного к продакшену

Сяомин отправил ссылку другу, и тот наконец увидел фичу рейтингов. «Неплохо!» — сказал друг.

Но Сяомин быстро заметил проблемы:

- Каждый перезапуск cloudflared меняет ссылку — приходится отправлять заново
- Компьютер должен работать всё время: закроет крышку ноутбука — друг отключается
- Друг говорит, что иногда грузится медленно — опыт нестабилен
- Хочется, чтобы увидело больше людей, но разослать ссылку каждому лично невозможно

Это не баги — естественные ограничения сетевого туннелирования. Оно и задумано как временное решение. Ваш компьютер — не сервер, а домашняя сеть — не дата-центр.

Хотите, чтобы продукт был надёжно доступен каждому — нужен **правильный деплой**: положить код на профессиональный сервер, чтобы он работал 24/7, имел стабильный адрес и достаточную пропускную способность.

Но перед деплоем нужно решить пререквизит: управление кодом. Сейчас ваш код существует только на вашем компьютере. Как его получит deploy-платформа? Ответ — **Git**, тема следующей главы.

Дорожная карта Сяомина проясняется:

1. **Git** (глава 11): запушить код на GitHub, чтобы deploy-платформы могли его спулить
2. **Деплой** (глава 12): задеплоить код на платформы вроде Vercel и получить стабильный публичный адрес
3. **Домены и HTTPS** (глава 13): настроить кастомный домен и включить шифрованные соединения

Каждый шаг стоит на предыдущем. Сетевое туннелирование помогло Сяомину валидировать «друзьям фича нравится». Дальше — превратить её в настоящий продукт.

::: tip Итоги главы

- localhost — loopback-адрес; localhost каждого устройства указывает на него самого
- Устройства на одном Wi-Fi могут обращаться друг к другу через локальные IP
- Firewall может блокировать доступ внутри локальной сети — возможно, потребуется разрешить соответствующий порт
- Сетевое туннелирование релеит запросы через публичный сервер, генерируя временную ссылку
- Туннелирование — временное решение; настоящий запуск требует деплоя (глава 12)
:::
