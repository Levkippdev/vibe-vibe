# 12.1 Деплой на EdgeOne Pages

> **Цель раздела**: задеплоить Next.js-проект на Tencent Cloud EdgeOne Pages и получить публично доступный URL.

Сяомин получил от друга сообщение: «Та ссылка, что ты показывал в прошлый раз, больше не открывается». Тогда он понял: временная ссылка Cloudflare Tunnel исчезает с закрытием терминала. Ему нужен **постоянно доступный** адрес — такой, чтобы любой мог открыть в любое время, включён его компьютер или нет.

Именно для этого и существует «деплой». В своей основе он прост: **облачный компьютер выполняет те же команды, что вы уже выполняли локально**. Локально вы запускаете `pnpm install` для установки зависимостей и `pnpm build` для сборки; платформа делает ровно то же — только остаётся онлайн 24/7 и даёт публичный URL.

EdgeOne Pages — edge-платформа деплоя Tencent Cloud. Быстрый доступ в Китае, крепкая поддержка Next.js и free tier, которого личным проектам более чем достаточно. Сяомин решил начать здесь.

## Три вещи, которые нужно подтвердить перед деплоем

Перед кликом «Deploy» Сяомину нужно подтвердить три вещи. Это не просто чек-лист — у каждого пункта реальная причина.

**Первое: код уже запушен на GitHub.** Платформе нужно спулить ваш код с GitHub. Если код существует только локально, платформа его не достанет. Это уже сделано в главе 11.

**Второе: `pnpm build` успешно проходит локально.** Это самый важный шаг. Локальная сборка падает — в облаке точно упадёт, потому что облако делает ровно то же, что ваша машина. Запустите `pnpm build` в терминале. Увидели «Build completed» — можно идти.

**Третье: зафиксируйте переменные окружения из `.env`.** Ещё в главе 6 вы узнали: файл `.env` исключён `.gitignore`, на GitHub он не попадает. Значит, в коде, который спулит платформа, не будет вашего пароля базы и auth-секрета — эти переменные придётся настроить на платформе вручную. Откройте локальный `.env` прямо сейчас и убедитесь, что знаете, какие там переменные и что означает каждая.

## Регистрация и подключение GitHub

Откройте [консоль EdgeOne Pages](https://console.cloud.tencent.com/edgeone/pages) и войдите через QR WeChat или аккаунт Tencent Cloud. Если вы впервые пользуетесь Tencent Cloud, потребуется пройти верификацию по реальному имени.

![image-20260227003947136](/images/Advanced/image-20260227003947136.png)

Кликните **Import Git** repository, затем выберите **Connect GitHub**.

При первом подключении вы попадёте на страницу авторизации GitHub. Тут выбор: авторизовать все репозитории или только определённые?

Сяомин выбрал «Only select repositories» и авторизовал только один репозиторий: «Личный Douban». Это следует **принципу минимальных привилегий**: дайте платформе только нужные ей права, ничего сверх. Захотите деплоить другие проекты позже — вернётесь и добавите. Эта привычка упоминалась в security-разделе главы 8 и так же применима к деплою.

После авторизации появится список репозиториев. Выберите проект для деплоя и кликните **Next**.

Разумеется, можно просто кликнуть загрузку — платформа обычно автодетектит фреймворк проекта.

![image-20260227005154181](/images/Advanced/image-20260227005154181.png)

## Настройка параметров сборки

Этот шаг говорит платформе, «как собирать ваш проект». EdgeOne автоматически заполнит рекомендуемые настройки по выбранному фреймворку, но стоит понимать смысл каждой опции — при сбое вы будете знать, куда смотреть.

![image-20260227005228223](/images/Advanced/image-20260227005228223.png)

Поставьте **Framework Preset** в Next.js. После выбора платформа автоматически заполнит build command и output directory — как телефон автоматически открывает .pdf файл PDF-ридером. Платформа распознаёт, что вы на Next.js, и уже знает, как его собирать.

**Root Directory** оставьте дефолтным `./`. Менять нужно, только если код проекта не в корне репозитория (например, в подкаталоге `apps/web/`). Проект Сяомина в корне — менять нечего.

**Build Command** — `pnpm build` (или `npm run build`). Это та же команда, что вы запускали локально: платформа выполняет точно ту же операцию в облаке.

**Output Directory** — `.next`. Сюда Next.js кладёт сгенерированные файлы после сборки; платформе нужно знать, где их искать.

**Node Version** — EdgeOne обычно ставит Node 22 по умолчанию, для большинства Next.js-проектов дефолт нормален. В целом, поначалу оставьте как есть. **Меняйте под локальную версию, только если в логах видите ошибку совместимости версий Node**.

![image-20260227005254177](/images/Advanced/image-20260227005254177.png)

## Настройка переменных окружения

На странице настроек сборки найдите секцию **Environment Variables** ближе к низу.

Помните, что мы только что говорили? `.env` на GitHub не уехал — эти переменные придётся ввести вручную. EdgeOne Pages поддерживает **bulk import**: просто вставьте содержимое `.env`, и платформа автоматически распарсит пары ключ-значение.![image-20260227005320209](/images/Advanced/image-20260227005320209.png)



Проекту Сяомина нужны эти переменные:

```bash
DATABASE_URL="postgresql://..."        # Строка подключения к базе; без неё приложение не подключится
BETTER_AUTH_SECRET="xxx"               # Auth-секрет; без него логин упадёт
BETTER_AUTH_URL="https://your-domain"  # Auth callback URL; пока оставьте пустым, обновите после деплоя
```

Каждая переменная служит своей цели. Нет `DATABASE_URL` — приложение упадёт на старте с «Cannot connect to database»; нет `BETTER_AUTH_SECRET` — логин юзеров упадёт с 500. Не уверены, какие переменные нужны, — откройте локальный `.env`: всё, что там есть, нужно настроить и здесь.

::: tip Передеплойте после изменения переменных
Изменения переменных окружения не вступают в силу автоматически. Нужно кликнуть «Redeploy», чтобы платформа пересобрала с новыми значениями.
:::

## Выбор региона ускорения

Это шаг, специфичный для платформ деплоя в Китае, связанный с ICP-файлингом.

![image-20260227005154181](/images/Advanced/image-20260227005154181.png)

Простыми словами: регион ускорения, включающий «Mainland China», требует ICP-файлинг. Вы наверняка видели строки «京ICP备xxxxxxxx号» в футере китайских сайтов — это номер ICP-файлинга. Китайские регуляции требуют от сайтов на серверах в материковом Китае пройти регистрацию до публичного доступа. Физлица тоже могут подать, но одобрение обычно занимает одну-две недели.

Сяомин не хотел ждать и выбрал **«Global (excluding Mainland China)»**. Этот вариант не требует файлинга — использовать можно сразу после деплоя. Несмотря на «excluding Mainland China», доступ из Китая после привязки кастомного домена тоже работает нормально — конфигурацию домена разберём в главе 13.

## (Опционально) Что делать, если сборка падает

Когда всё настроено, первый деплой обычно сразу проходит успешно.

![image-20260302003046402](/images/Advanced/image-20260302003046402.png)

Если и у вас красный **Failed** — читайте этот раздел. **Логи сборки — ваш важнейший источник информации: ответ обычно в последних строках.**

Например, частая ошибка:

```
error engine "node" is incompatible with this module
```

Это значит: версия Node несовместима. Лечение простое: вернитесь к настройкам сборки, поменяйте версию Node под требования проекта и кликните **Redeploy**.

![image-20260227005254177](/images/Advanced/image-20260227005254177.png)

После передеплоя обычно гладко наступает зелёный **Success**.

## Деплой успешен: получите ссылку

После успешной сборки платформа генерирует preview-ссылку формата `xxx.edgeone.dev`.

![image-20260302003255608](/images/Advanced/image-20260302003255608.png)

Сяомин открыл ссылку и увидел свой «Личный Douban» — в точности как локальная версия, только теперь живущую в публичном интернете. Он отправил ссылку другу; тот открыл мгновенно и ответил: «Наконец-то работает!»

Это самый вдохновляющий момент туториала на данный момент: **ваш код теперь доступен всему миру.**

::: warning Ограничения preview-ссылки
Если выбран регион ускорения «Global (excluding Mainland China)», дефолтный домен может иметь ограничения доступа (3-часовой срок валидности). **Ограничение исчезает после привязки кастомного домена**. Детали настройки домена — [Глава 13](../13-domain-dns/index.md).
:::

## Разбор частых ошибок сборки

Проблема версии Node у Сяомина — лишь самая частая. Если сборка падает и у вас, начните с ключевых слов ошибки в последних строках логов:

| Ключевое слово | Причина | Решение |
|-----------|------|---------|
| `engine "node" is incompatible` | Несовпадение версии Node | Поправить версию Node в настройках |
| `Cannot find module` | Провал установки зависимостей | Проверить, закоммичены ли `package.json` и lockfile на GitHub |
| `DATABASE_URL is not defined` | Не настроена переменная окружения | Добавить на странице переменных |
| `Build failed` без деталей | Неверная build command | Убедиться, что команда совпадает с локальной |
| `ENOENT: no such file` | Неверный путь | Проверить конфигурацию root directory |

Попалась непонятная ошибка? Скопируйте логи в Claude Code — пусть поможет диагностировать. Информации в логах сборки обычно достаточно, чтобы локализовать проблему.

## Push to deploy

После подключения GitHub каждый `git push` в основную ветку автоматически триггерит передеплой EdgeOne Pages. Вручную делать ничего не нужно — это начало CI/CD, детально разберём в [12.3](./03-cicd-automation.md).

В этом туториале есть EdgeOne-скилл деплоя. Установив, просто скажите Claude Code «Помоги задеплоить этот проект на EdgeOne Pages» — и он проведёт через весь процесс.

Как установить: отправьте Claude Code следующую ссылку — он автоматически распознает и установит Skill:

```

```

Но понимать ручные шаги выше по-прежнему важно: когда автоматизация ломается, нужно знать, где разбираться.
