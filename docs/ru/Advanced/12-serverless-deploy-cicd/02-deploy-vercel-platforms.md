# 12.2 Деплой на платформы типа Vercel

> **Цель раздела**: понять воркфлоу деплоя на Vercel и похожие платформы и выбрать ту, что лучше подходит вашему проекту.

После деплоя «Личного Douban» Сяомина на EdgeOne Pages друг спросил: «Я тоже хочу задеплоить свой проект, но большинство моих юзеров за рубежом. Какую платформу выбрать?»

Отличный вопрос. EdgeOne Pages хорош для юзеров в Китае, но далеко не единственная платформа деплоя. Хорошая новость: всё изученное в 12.1 — подключение GitHub, настройка сборки и переменные окружения — работает одинаково на любой платформе. Отличаются только вид UI, щедрость free tier и то, где доступ быстрее.

## Обзор платформ

Начнём с высоты птичьего полёта, чтобы понять позиционирование главных платформ:

| Платформа | Доступ из Китая | Free tier | Особенности | Для кого |
|------|---------|---------|------|---------|
| **Vercel** | Медленнее (нужен кастомный домен) | 100 ГБ bandwidth/мес | Официальная платформа Next.js, лучший developer experience | Зарубежные юзеры, личные проекты |
| **Cloudflare Pages** | Быстрее | Безлимитный трафик | Глобальный CDN, edge-вычисления Workers | Статика-first сайты, можно деплоить Next.js |
| **Alibaba Cloud ESA** | Быстро | Есть free tier | Экосистема Alibaba Cloud, быстрый доступ в Китае | Юзеры в Китае, пользователи Alibaba Cloud |
| **Netlify** | Медленнее | 100 ГБ bandwidth/мес | Встроенная обработка форм и аутентификация | Статические сайты, JAMstack |
| **Railway** | Средне | $5 бесплатного кредита/мес | Поддерживает базы и backend-сервисы | Full-stack приложения, нужен backend |

Детали каждой платформы запоминать не нужно. Дальше разберём самые важные по одной — и вы увидите, что ключевой воркфлоу везде один и тот же.

## Vercel: «родительская компания» Next.js

Vercel — создатель Next.js и официально рекомендованная платформа деплоя Next.js-проектов. Если ваш проект на Next.js, Vercel даст самый гладкий опыт: нативно поддерживает каждую фичу Next.js без дополнительной конфигурации.

### Воркфлоу деплоя

**Вариант 1: через web-UI (рекомендуется новичкам)**

Откройте [vercel.com](https://vercel.com) и войдите через аккаунт GitHub.

![image-20260302004336073](/images/Advanced/image-20260302004336073.png)

Кликните **Add New → Project** и выберите репозиторий GitHub. Vercel автоматически детектит фреймворк Next.js — обычно менять придётся немного.

![image-20260302004314090](/images/Advanced/image-20260302004314090.png)

Нужно сделать всего две вещи:

1. Добавить переменные окружения (как в EdgeOne — вставить содержимое `.env`)
2. Кликнуть **Deploy**

![image-20260302004247091](/images/Advanced/image-20260302004247091.png)

После успеха получите ссылку вида `xxx.vercel.app`.

**Вариант 2: из командной строки (быстрее)**

Предпочитаете командную строку — используйте Vercel CLI:

```bash
# Установка Vercel CLI
npm i -g vercel

# Логин (откроет браузер для авторизации)
vercel login

# Деплой (при первом запуске спросит конфигурацию проекта)
vercel deploy

# Деплой в продакшен
vercel --prod
```

При первом `vercel deploy` CLI спросит имя проекта, привязку к существующему и т.д. После этого каждый `vercel deploy` — деплой одной командой, заметно быстрее web-UI.

Весь процесс почти идентичен EdgeOne: подключить GitHub, настроить сборку, задать переменные окружения, кликнуть деплой.

::: warning Проблемы доступа к Vercel из Китая
Домен `*.vercel.app` нестабилен при доступе из Китая. Решение — привязать кастомный домен и использовать Cloudflare как DNS-прокси для ускорения. Конфигурация домена — глава 13.
:::

### Уникальные преимущества Vercel

Vercel не просто «деплоит ваше приложение» — он делает много дополнительной работы для developer experience.

**Preview Deployments** — самая практичная фича. Каждый раз при создании Pull Request Vercel автоматически генерирует отдельную preview-ссылку для этого PR. Можно отправить её друзьям — они увидят результат до мержа кода. Это идеально сочетается с PR-воркфлоу из главы 11: ревью кода и тест фичи прямо по preview-ссылке одновременно.

![image-20260302005118317](/images/Advanced/image-20260302005118317.png)

**Дашборд аналитики** — одна из value-added фич Vercel, но в большинстве случаев полные данные появятся только после интеграции соответствующих компонентов в проект (вроде Analytics / Speed Insights). Точные шаги лучше смотреть прямо в дашборде Vercel и официальной документации: точки входа могут различаться по версии фреймворка и тарифу.

![image-20260302005153216](/images/Advanced/image-20260302005153216.png)

**Edge Functions** реплицируют ваш код по узлам CDN по всему миру. Обычно API-роуты работают на одном фиксированном сервере: юзер в Пекине или Нью-Йорке — каждый запрос едет в одно место на обработку. Edge Functions позволяют динамической логике работать ближе к юзеру: запрос обрабатывается на ближайшем узле, без объезда.



## Cloudflare Pages: очарование безлимитного трафика

Главная фишка Cloudflare Pages — **безлимитный трафик**: бесплатный тариф не ограничивает трафик. Для личных проектов это значит: о стоимости трафика можно вообще не думать. Даже если статья внезапно завирусится и приведёт лавину посетителей, доплаты не будет.

### Быстрый воркфлоу деплоя

Чтобы быстро попробовать деплой Next.js на Cloudflare Pages, можно сразу пройти:

**https://workers.new/templates/next-starter-template**

Это быстрый лаунчер Next.js-шаблона от Cloudflare. Клик — и он автоматически:
1. Создаст новый репозиторий под вашим GitHub-аккаунтом (на базе Next.js-шаблона)
2. Подключит его к Cloudflare Pages
3. Завершит первый деплой автоматически

Весь процесс меньше 2 минут — и Next.js-приложение работает на edge-сети Cloudflare. Быстрейший способ ощутить возможности платформы; после этого можно превратить шаблонный репозиторий в свой проект или деплоить существующий по шагам ниже.

### Деплой существующего проекта

Хотите задеплоить собственный Next.js-проект:

1. Войдите в [Cloudflare Dashboard](https://dash.cloudflare.com)
2. Перейдите в **Workers & Pages → Create**

![image-20260302005022505](/images/Advanced/image-20260302005022505.png)

3. Подключите GitHub и выберите репозиторий
4. Настройте сборку (framework preset — Next.js)
5. Добавьте переменные окружения
6. Кликните деплой

![image-20260302005442304](/images/Advanced/image-20260302005442304.png)

Видите? Шаги почти идентичны EdgeOne и Vercel.

![image-20260302005452914](/images/Advanced/image-20260302005452914.png)

![image-20260302012941453](/images/Advanced/image-20260302012941453.png)

### Уникальные преимущества Cloudflare

Помимо безлимитного трафика, у Cloudflare полная экосистема edge-вычислений. **Workers** — их версия Edge Functions: код тоже исполняется на узлах CDN, просто под другим именем. **D1** — собственная лёгкая база Cloudflare, созданная работать с Workers; ваш текущий Neon PostgreSQL уже более чем достаточен, D1 — просто ещё одна опция внутри экосистемы Cloudflare. **R2** — объектное хранилище, совместимое с S3 API. Если проекту в будущем могут понадобиться edge-вычисления, Cloudflare — сильный вариант.



## Alibaba Cloud ESA Pages: ещё одна опция в Китае

Если вы уже пользователь Alibaba Cloud или проект нацелен на юзеров в Китае, Alibaba Cloud ESA (Edge Security Acceleration) — ещё один вариант помимо EdgeOne.

### Воркфлоу деплоя

1. Войдите в [консоль Alibaba Cloud ESA Pages](https://esa.console.aliyun.com/edge/pages/list)
2. Создайте проект Pages и подключите GitHub
3. Настройте сборку и переменные окружения
4. Выберите регион ускорения (как в EdgeOne, для материкового Китая нужен ICP-файлинг)
5. Задеплойте

![image-20260302013222049](/images/Advanced/image-20260302013222049.png)

ESA позиционируется похоже на EdgeOne: обе — edge-платформы деплоя китайских облачных провайдеров. Что выбрать — в основном зависит от того, с какой экосистемой вы лучше знакомы. Если уже пользуетесь другими сервисами Alibaba Cloud (OSS, RDS), с ESA удобнее: аккаунт и биллинг останутся в одной системе.

## Ключевой воркфлоу одинаков на всех платформах

К этому моменту вы наверняка заметили закономерность: какую платформу ни выбери, ключевой воркфлоу — всегда эти пять шагов:

```
Подключить GitHub → Выбрать репозиторий → Настроить сборку → Добавить переменные окружения → Деплой
```

Это не совпадение. Все эти платформы решают одну проблему: превратить код из репозитория GitHub в сайт, доступный людям. Логика одна; различаются только интерфейс, free tier и покрытие сети.

**Проведя полный деплой на EdgeOne, вы быстро освоитесь на любой другой платформе.** Как выучить вождение на одной машине: пересесть на другую — лишь привыкнуть к расположению приборов.

## Как выбирать

Выбор платформы — как выбор телефона: большинство ключевых функций схожи, берите ту, что ощущается удобной. Но если нужен гайд по решению:

**Большинство юзеров в Китае?** Берите EdgeOne Pages или Alibaba Cloud ESA. У китайских облачных провайдеров покрытие edge-узлов в Китае лучше — доступ быстрее.

**Большинство юзеров за рубежом?** Vercel (особенно для Next.js-проектов) или Cloudflare Pages. Vercel — лучший developer experience; у Cloudflare самый щедрый free tier.

**Юзеры по всему миру?** Cloudflare Pages с безлимитным трафиком + глобальный CDN — вариант без забот. С кастомным доменом доступ быстрый и внутри, и вне Китая.

**Не уверены?** Просто выберите одну и запуститесь. Даже «неправильный» выбор не страшен: все платформы работают через подключение GitHub + настройку сборки, поэтому смена платформы — лишь раз повторить сетап на новой. Код менять не придётся. Стоимость миграции практически нулевая.

::: tip Не переусердствуйте в раздумьях
Выберите одну и запуститесь — сменить всегда можно позже. Ваш код живёт на GitHub и не зависит от конкретной платформы. Поэтому в главе 6 мы подчёркивали «держать архитектуру независимой»: стандартные подключения к базе, стандартные фреймворки — и никакого лок-ина ни в одну платформу.
:::

Какую бы платформу вы ни выбрали, можно сказать Claude Code напрямую:

Claude Code проведёт через весь процесс. Но после 12.1 и этого раздела вы уже понимаете ключевые концепции деплоя — и при сбое не будете чувствовать себя полностью потерянным.
