# 14.2 Инициализация VPS и security-конфигурация

> **Цель раздела**: пройти первое подключение к серверу, обновление системы, установку 1Panel и security-харднинг — сделать сервер одновременно удобным и защищённым.

Сяомин открывает терминал, готовясь впервые подключиться к своему серверу.

## Шаг 1: Подключение к серверу

После покупки сервера вы получите три вещи: **публичный IP**, **имя юзера** (обычно `root`) и **пароль**.

::: tip Что такое SSH?
SSH — это дистанционное управление. Ваш компьютер — пульт, сервер — телевизор, а SSH — невидимый инфракрасный луч, позволяющий управлять далёкой машиной из дома. Принципы SSH и настройку ключей вы прошли в главе 10; теперь применим их на практике.
:::

### Способ 1: Безпарольный логин через консоль провайдера (рекомендуется новичкам)

Простейший путь — веб-терминал облачного провайдера:

1. Откройте консоль сервера
2. Перейдите на страницу обзора сервера
3. Кликните «Password-Free Login / Login» в секции «Remote Login»
4. Браузер автоматически откроет веб-терминал, где можно вводить команды

![Tencent Cloud Lighthouse Server Console Overview](/images/Advanced/14-vps-ops-deploy/14-2-server-console-01.png)

![Web Terminal Entry](/images/Advanced/14-vps-ops-deploy/14-2-web-terminal-02.png)

Сяомин кликает «Password-Free Login», и в браузере всплывает чёрное окно терминала. Промпт показывает `root@xxx:~#` — «Я внутри!» Он пробует набрать `ls` — на экране ничего не появляется: пусто. Затем набирает `pwd` — показывает `/root`. Это его сервер: чистая, пустая система, ждущая, когда он начнёт что-то ставить.

### Способ 2: SSH-логин из локального терминала

Если предпочитаете работать в локальном терминале (удобнее для постоянной работы), откройте терминал компьютера (PowerShell на Windows, Terminal на Mac) и наберите:

```bash
ssh root@your-server-ip
```

При первом подключении вы увидите запрос подтверждения fingerprint:

```
The authenticity of host '1.2.3.4' can't be established.
ED25519 key fingerprint is SHA256:xxxxx...
Are you sure you want to continue connecting (yes/no)?
```

Наберите `yes` и Enter, затем введите пароль. Об успехе скажет смена промпта на `root@xxx:~#`.



::: tip Невидимость ввода пароля — это нормально
При вводе пароля в терминале на экране не появляется ни одного символа (даже звёздочек). Это security-фича Linux — просто набирайте уверенно и жмите Enter.
:::

### Способ 3: FinalShell (удобнее для ежедневного управления)

Если хочется терминал с nicer-интерфейсом плюс файловый менеджер, можно использовать FinalShell (официальный сайт: https://www.hostbuf.com/t/988.html).

1. Откройте FinalShell → New Connection
2. Host: публичный IP сервера
3. Username: `root`
4. Password: пароль, заданный при покупке
5. Кликните OK, дважды кликните по настроенному серверу для подключения

![FinalShell Connection Interface](/images/Advanced/14-vps-ops-deploy/14-2-finalssh-03.png)

![SSH Connection Success](/images/Advanced/14-2-ssh-success-04.png)

## Шаг 2: Обновление системы

Старый мастер говорит: «Не воодушевляйтесь раньше времени — сначала заприте двери и окна. Голый сервер в интернете в среднем сканируется за считанные минуты».

Первое дело после логина — обновление системных пакетов:

```bash
apt update && apt upgrade -y
```

Сяомин жмёт Enter, и экран начинает стремительно скроллиться — строки с именами пакетов мелькают одна за другой. Минуты через две-три обновление завершается.

Это как патчинг нового компьютера после установки ОС. `apt update` обновляет список пакетов, `apt upgrade` ставит все доступные обновления.

![apt update process](/images/Advanced/14-vps-ops-deploy/14-2-apt-update-05.png)

![apt upgrade process](/images/Advanced/14-vps-ops-deploy/14-2-apt-upgrade-06.png)

::: tip Конфигурационные промпты при обновлении
Если всплывают страницы конфигурации — просто жмите Enter, оставляя дефолты. Сервер может попросить рестарт после обновлений — это нормально. Если соединение оборвётся посередине, просто переподключитесь.
:::

## Шаг 3: Установка базовых инструментов

Скопируйте эту команду в терминал, чтобы поставить инструменты, которые не раз пригодятся при управлении сервером:

```bash
apt install vim git curl wget htop unzip rsync jq git-lfs lsof nload net-tools dnsutils -y
```

Что делают эти инструменты:

| Инструмент | Назначение | Примеры сценариев |
|------|---------|-------------------|
| vim | Текстовый редактор в терминале | Редактирование конфигов |
| git | Система контроля версий | Пуллинг/пушинг кода |
| curl / wget | Скачивание файлов и тестирование API | Дебаг API, сетевой траблшутинг |
| htop | Визуальный монитор системных ресурсов | Проверка нагрузки CPU, памяти |
| unzip | Распаковка zip-архивов | Разархивирование загруженных архивов |
| rsync | Эффективный синк и бэкап | Миграция сайта одним кликом |
| jq | Форматирование JSON | Обработка вывода API и логов |
| lsof | Проверка занятости портов | Траблшутинг конфликтов сервисов |
| nload | Мониторинг сетевого трафика в реальном времени | Проверка забит ли bandwidth |
| net-tools | Набор ifconfig / netstat | Сетевой траблшутинг |
| dnsutils | dig / nslookup | Проверка DNS-резолвинга |

Сяомин смотрит на эту длинную команду с мыслью: «Неужели мне правда нужны все эти инструменты?» Старый мастер отвечает: «Сейчас, может, и нет — но когда возникнут проблемы, эти инструменты спасут вам жизнь».

## Шаг 4: Установка 1Panel

1Panel — современная панель управления Linux-сервером, позволяющая управлять сервером через веб-интерфейс без заучивания десятков команд. Вы уже пользовались веб-консолями облачных провайдеров для покупки серверов — 1Panel приносит похожий интерфейс управления на ваш собственный сервер: рулить всем из браузера, не набирая команды для каждой мелочи.

Установка одной строкой:

```bash
curl -sSL https://resource.fit2cloud.com/1panel/package/quick_start.sh -o quick_start.sh && bash quick_start.sh
```

В процессе установки вас попросят задать:

- **Порт панели**: смените на нестандартный (например, `29876`), не используйте дефолтный
- **Имя юзера панели**: не используйте `admin`
- **Пароль панели**: задайте надёжный

После установки терминал покажет URL доступа к панели: `http://your-ip:port/security-entry`

![1Panel Installation Process](/images/Advanced/14-vps-ops-deploy/14-2-1panel-install-07.png)

![1Panel Installation Complete](/images/Advanced/14-vps-ops-deploy/14-2-1panel-install-10.png)

::: tip Запомните security entry
URL доступа 1Panel включает случайный **security entry path** (например, `/abc123`). Даже если кто-то узнает ваш IP и порт, без этого пути панель он не откроет. **Обязательно запишите его**.
:::

## Шаг 5: Настройка security groups (firewall провайдера)

Прежде чем открывать 1Panel в браузере, нужно настроить **security groups** в консоли облачного провайдера.

::: tip Что такое security groups?
Security groups — охрана у двери дата-центра. По умолчанию разрешён только SSH (порт 22) — всё остальное заперто. Когда ставите новые приложения с новыми портами, вы обязаны сказать охраннику: «открой ещё и порт XX».
:::

Порты, которые нужно открыть:

| Порт | Назначение | Протокол |
|------|---------|----------|
| 22 | SSH-подключение | TCP |
| 80 | HTTP-доступ к сайту | TCP |
| 443 | HTTPS-доступ к сайту | TCP |
| Порт панели | Доступ к 1Panel (задан при установке) | TCP |

Сяомин открывает консоль Tencent Cloud, находит страницу «Firewall» (у разных провайдеров названия разные: Alibaba Cloud зовёт «Security Groups», Tencent Cloud Lighthouse — «Firewall»). Он добавляет правила по таблице: выбирает протокол, вводит номер порта, ставит «Allow» для каждого. Ничего сложного, но в первый раз немного занудно — потом привыкнете.

![Tencent Cloud Firewall Add Rule](/images/Advanced/14-vps-ops-deploy/14-2-security-group-14.png)

::: warning Security groups vs системный firewall
Security groups провайдера и системный firewall сервера (например, `ufw`) — **две отдельные двери**. Чтобы трафик проходил, обе должны быть открыты. Много новичков открывают лишь одну и не могут понять, почему к серверу не достучаться.
:::

Настроив security groups, откройте URL 1Panel в браузере и войдите с вашим именем юзера и паролем.

![1Panel Login Page](/images/Advanced/14-vps-ops-deploy/14-2-1panel-login-11.png)

![1Panel Main Interface](/images/Advanced/14-vps-ops-deploy/14-2-1panel-dashboard-12.png)

Сяомин видит веб-консоль — «Это куда дружелюбнее командной строки». На главной странице панели — realtime-статус сервера: нагрузка CPU, потребление памяти, место на диске, сетевой трафик — всё как на ладони. В меню слева: App Store, Container Management, Database, Website, Scheduled Tasks... Сяомин кликает туда-сюда с ощущением, что установил серверу десктопную ОС.

![Container Monitoring Panel](/images/Advanced/14-3-1-monitor-10.png)

## Шаг 6: Установка Docker и настройка mirror acceleration

После логина в 1Panel система проведёт вас через установку Docker — просто кликните one-click install.

После установки Docker критически важно **настроить mirror acceleration**. Это то же, что настроить Taobao-зеркала для npm: Docker Hub — зарубежный registry, и без ускорителей загрузка мучительна. 1Panel при установке Docker спросит, настроить ли mirror acceleration автоматически (жмите y), либо позже поправьте вручную в «Containers > Configuration».

Настроив ускорение, Сяомин пробует поставить приложение — готово за секунды. Раньше без ускорения он ждал десять минут без какого-либо прогресса.

::: warning Mirror acceleration обязателен в Китае
Без mirror acceleration вы, скорее всего, застрянете на «pulling image» при установке приложения — вечное ожидание с последующим timeout. С нормальным ускорением образы скачиваются за секунды.
:::

## Шаг 7: Security-харднинг сервера

Старый мастер говорит: «Следующие шаги — **не опция**, а **обязаловка**».

Сяомин не совсем понимает: «На моём сервере пока нет важных данных — кто на меня нападёт?» Старый мастер открывает страницу логов 1Panel, тыча в сотни проваленных попыток SSH-логина со всего мира: «Видите? Ваш сервер в онлайне меньше часа, а brute force попыток уже сотни. Это автоматические сканирующие скрипты — им всё равно, кто вы, они пробуют любой открытый порт».

Сяомин пробегает глазами эти IP-адреса — Россия, Бразилия, Вьетнам... «Ладно, запирать двери и окна действительно нужно».

### 7.2 Смена дефолтного SSH-порта

Дефолтный порт 22 — первоочередная цель хакеров. Сменить его можно прямо в 1Panel:

1. Перейдите в «System > SSH Management»
2. Найдите «Connection Port», кликните кнопку «Settings» рядом и в попапе смените на нестандартный порт (например, `24324`)

![1Panel SSH Management Page](/images/Advanced/14-vps-ops-deploy/14-2-ssh-port-19.png)

После смены не забудьте **открыть новый порт** и в security group провайдера, и в «System > Firewall» 1Panel, затем проверьте с новым портом:

```bash
ssh -p 24324 root@your-server-ip
```

Сяомин открывает новое окно терминала и подключается с новым портом — успешно. Облегчённо выдохнув, он возвращается в консоль провайдера и удаляет старое правило для порта 22.

::: warning Проверьте перед закрытием старого порта
После смены SSH-порта **не спешите закрывать порт 22**. Закрывайте только после успешного подключения с новым портом. Иначе, если конфигурация нового порта неверна, вы запрёте себя снаружи.
:::

### 7.3 Включение Fail2Ban

::: tip Что такое Fail2Ban?
Fail2Ban — автоматический чёрный список. Кто-то пять раз подряд ввёл неверный пароль? Его IP блокируется немедленно — как банковская карта, залоченная после слишком многих неверных попыток ввода PIN.
:::

В 1Panel пройдите в «Toolbox > Fail2Ban». Если горит красное «Not Installed», кликните «Install Now» — 1Panel поставит всё автоматически. После установки можно визуально управлять правилами бана в панели. Дефолтной конфигурации достаточно: после 5 проваленных SSH-попыток IP банится.

![Fail2ban Installation](/images/Advanced/14-vps-ops-deploy/14-2-fail2ban-24.png)

Не забудьте сменить порт мониторинга на тот, что вы задали ранее.

![Fail2ban Configuration](/images/Advanced/14-vps-ops-deploy/14-2-fail2ban-25.png)

Поставив Fail2Ban, Сяомин снова проверяет логи и видит, что brute force IP уже забанены автоматически. «Как поставить автозамок на дверь: слишком много неверных попыток — и тебя не пускают».

### 7.4 Настройка SSH-логина по ключу (замена пароля)

Каким бы сложным ни был пароль, его можно перебрать brute force'ом. SSH-логин по ключу безопаснее: зайти могут только устройства с приватным ключом, и перебор паролей становится полностью бесполезен.

#### Генерация SSH-ключа на локальном компьютере

Юзеры Windows открывают PowerShell, Mac/Linux — Terminal, и выполняют:

```bash
ssh-keygen -t rsa -b 4096
```

Жмите Enter несколько раз, принимая дефолты (дефолтный путь и пустая passphrase).

После генерации посмотрите содержимое публичного ключа:

```bash
cat ~/.ssh/id_rsa.pub
```

Вы увидите что-то вроде (это и есть «публичный ключ»):

```
ssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAABAQC...
```

![Windows PowerShell Generate SSH Key](/images/Advanced/14-vps-ops-deploy/14-2-ssh-keygen-15.png)

::: tip Публичный ключ vs приватный
- **Публичный ключ** (`id_rsa.pub`) можно свободно шарить, загружать на серверы
- **Приватный ключ** (`id_rsa`) храните в безопасности и никогда не сливайте. Приватный ключ — ваш «ключ»: потерять его — как потерять ключ от дома
:::

#### Загрузка публичного ключа на сервер

В 1Panel пройдите: `System → SSH Management`

Настройте:

| Пункт | Значение |
|------|---------|
| Key Authentication | ✅ Enabled |
| Authorized Keys | Кликните кнопку «Authorized Keys», вставьте скопированный публичный ключ |
| Password Authentication | ❌ Disabled (только после подтверждения работы ключа) |

![1Panel SSH Key Management](/images/Advanced/14-vps-ops-deploy/14-2-ssh-key-mgr-16.png)

После сохранения **не закрывайте текущее SSH-соединение**. Откройте новое окно терминала и проверьте вход по ключу:

```bash
ssh -p 24324 root@your-server-ip
```

Если логин прошёл напрямую (без ввода пароля) — настройка ключа успешна. Теперь вернитесь в 1Panel, отключите «Password Authentication» и кликните «Restart SSH Service».

Сяомин подтверждает работу ключа и отключает парольную аутентификацию. Он проверяет в новом окне: вход по ключу проходит, вход по паролю отклоняется. «Теперь brute force по паролю совершенно бесполезен».

::: warning Проверьте перед отключением пароля
Перед отключением парольного входа **абсолютно убедитесь, что вход по ключу работает**. Иначе при ошибке конфигурации вы запрёте себя снаружи, и починить можно будет только через веб-терминал провайдера.
:::

### 7.5 Включение WAF (опционально, но настоятельно рекомендуется)

Если позже привяжете домен к сайту, можно бесплатно включить **WAF (Web Application Firewall)** в расширенных фичах 1Panel. Его основная задача — помогать сайту автоматически блокировать частые malicious-запросы: сканирование, brute force, SQL-инъекции и т.д. — по сути «добавить дефолтный замок».

Как включить:

1. В 1Panel пройдите: `Advanced Features → WAF`
2. Переключитесь на «Global Settings»
3. Включите «Access Frequency Limit» (защита от malicious-рефрешей, CC-атак)
4. Сохраните

![1Panel WAF Configuration](/images/Advanced/14-vps-ops-deploy/14-2-waf-28.png)

WAF не мешает нормальному доступу. Даже без дополнительной security-конфигурации он заметно снижает malicious-трафик.

## Чек-лист ежедневного обслуживания

Сервер — это не «настроил и забыл». Хорошая новость: большинство обслуживания делается в интерфейсе 1Panel:

| Операция | Как в 1Panel | Альтернатива в командной строке |
|-----------|---------------|--------------------------|
| Посмотреть нагрузку системы | Дашборд на главной панели или «System > Monitoring» для детальных графиков | `htop` |
| Проверить место на диске | Использование диска внизу главной страницы | `df -h` |
| Почистить Docker-мусор | Выполнить cleanup-команду в терминале панели | `docker system prune -f` |
| Обновление системы | Выполнить в терминале панели | `apt update && apt upgrade -y` |
