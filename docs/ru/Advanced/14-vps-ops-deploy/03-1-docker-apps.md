# 14.3.1 Магазин приложений и основы Docker

> **Цель раздела**: понять ключевые концепции Docker и научиться одним кликом ставить и управлять разными сервисами через магазин приложений 1Panel.

Сяомин открыл магазин приложений 1Panel и увидел аккуратно разложенные базы данных, веб-серверы и инструменты мониторинга: «Разве это не как мобильный app store? Клик — и установлено».

## Что же такое Docker?

Старожил сказал: «Приложения на вашем телефоне — установочные пакеты, скачанные из app store: клик — и они стоят. Docker повторяет ту же идею, только для серверов».

- **Образ (Image)**: как установочный пакет в app store. «Образ PostgreSQL 18» — упакованный установщик базы, содержащий все нужные файлы и конфигурации.
- **Контейнер (Container)**: как запущенное приложение на телефоне. Разница в том, что здесь один и тот же установочный пакет можно «установить» несколько раз, и каждый экземпляр работает независимо, не мешая соседям.
- **Registry**: как app store. Docker Hub — крупнейший «серверный app store» с сотнями тысяч готовых пакетов приложений.

::: tip Зачем нужен Docker?
Без Docker пришлось бы вручную ставить PostgreSQL, конфигурировать Redis, тюнить OpenResty на сервере... У каждой программы свой способ установки, конфликты версий и недостающие зависимости — обычное дело. С Docker каждое приложение работает в собственном «грузовом контейнере», изолированно от других. Напортачили — просто удалите и начните заново: система сервера остаётся чистой.
:::

## Магазин приложений 1Panel

1Panel оборачивает операции Docker в графический интерфейс. Откройте «App Store» панели — увидите разное часто используемое ПО, ставится кликом.

![1Panel App Store page](/images/Advanced/14-vps-ops-deploy/14-3-1-appstore-01.png)

Частые приложения одним взглядом:

| Приложение | Назначение | Рекомендация по установке |
|-------------|---------|----------------------------|
| PostgreSQL | Реляционная база данных | Обязательна для проектов, задайте надёжный пароль |
| Redis | База-кэш | Ставьте, когда нужны кэширование или управление сессиями |
| OpenResty | Веб-сервер/reverse proxy | Обязателен при привязке домена |
| Node.js | Запуск Node.js-проектов | Нужен при деплое Next.js и похожих проектов |

::: tip Что такое OpenResty?
**OpenResty** — высокопроизводительный веб-сервер, построенный на Nginx. Его функции:
1. **Обрабатывать HTTP-запросы**: принимать запросы юзеров
2. **Отдавать статические файлы**: возвращать HTML, CSS, JS, картинки и т.д.
3. **Reverse proxy**: форвардить API-запросы на backend-сервисы
4. **Привязывать домены**: дать сайту доступ по доменному имени

Проще говоря, OpenResty — «парадная дверь» вашего сайта: когда юзеры заходят на ваш домен, OpenResty встречает их первым. Если хотите привязать домен (например, `yourdomain.com`), без OpenResty не обойтись.
:::

В «Advanced Settings» можно было выбрать, открывать ли внешние порты, задать лимиты ресурсов и т.д. Он заполнил всё по подсказкам и кликнул подтверждение — всплыло окно логов, прогресс-бар бежал секунд пятнадцать, и статус сменился на «Running». Весь процесс оказался куда проще, чем он думал. После установки приложение видно на странице «App Store - Installed».

### DBMS vs Database: первый шаг после установки базы

После установки PostgreSQL старожил велел Сяомину пройти на страницу «Database - PostgreSQL» в левом меню и создать конкретную базу (например, `my_app_db`).

«Погодите, я же только что установил базу? Зачем создавать ещё одну?»

Старожил объяснил: «Вы установили **СУБД (DBMS)** — это как поставить программу Excel. Но `.xlsx`-файл вы ещё не создали. Один раз поставив PostgreSQL, вы можете создать бесчисленное количество независимых баз для разных проектов».

Сяомин кликнул «Create Database» на странице «Database - PostgreSQL», заполнил имя базы, юзера, пароль, выбрал права доступа — и база создалась за секунды. Кликнув кнопку «Connection Info» над списком, он увидел адрес, порт, админ-имя и пароль — именно это понадобится позже при конфигурации `.env`.

::: tip DBMS vs Database
- **DBMS** (Database Management System): как PostgreSQL, MySQL — софт, управляющий данными
- **Database**: конкретная база, созданная внутри DBMS, например `myapp_db`

Аналогия: DBMS — это здание, Database — комната в этом здании. Из магазина 1Panel вы ставите «здание» (DBMS), а затем создаёте «комнаты» (Databases) для своих приложений.

**Подробно про проектирование и операции с базами — в главе 6 «Персистентность данных и базы данных».**
:::

## Управление контейнерами

После установки приложений управлять контейнерами можно в двух местах:

- **«App Store - Installed»**: управление приложениями, установленными через магазин, с поддержкой rebuild, рестарта, старта, стопа, удаления, просмотра параметров и прочих операций. Кнопка «Parameters» открывает просмотр и правку конфигурационных параметров приложения.
- **«Containers»**: управление всеми Docker-контейнерами (и из магазина, и созданными вручную). Каждый контейнер — строка с кнопками «Terminal» и «Logs» и меню «More» (edit, upgrade, monitor, create image, delete, rename).

Сяомин зашёл на страницу «Containers» и увидел работающие PostgreSQL и OpenResty, у каждого зелёный индикатор «Running».

![1Panel container list page](/images/Advanced/14-vps-ops-deploy/14-3-1-container-list-20.png)

Частые операции:

| Операция | Где выполнять | Описание | Эквивалентная команда |
|-----------|-----------------|-------------|------------------|
| Start/Stop/Restart | «Installed» или «Containers» | Управление статусом контейнера | `docker start/stop/restart container_name` |
| Просмотр логов | «Containers» → строка → Logs | Фильтры по времени, realtime-слежение, скачивание | `docker logs container_name` |
| Вход в терминал | «Containers» → строка → Terminal | Выбор команды (например, /bin/bash) и юзера | `docker exec -it container_name bash` |
| Просмотр мониторинга | «Containers» → строка → More → Monitor | CPU, память, дисковый IO, сеть | `docker stats container_name` |
| Rebuild | «Installed» → Rebuild | Удалить и пересоздать контейнер по текущей конфигурации, персистентные данные сохраняются | — |

Сяомин увидел только что установленный PostgreSQL на странице «Installed» с зелёным «Running». Кликнул «Stop» — статус стал красным; кликнул «Start» — восстановился за секунды. Это ощущение контроля убедило его: Docker действительно удобен — приложения как на телефоне, выключай и включай когда угодно.

::: tip Логи — ваш лучший друг
Когда с приложением что-то не так, первая реакция должна быть не «бежать в поисковик», а **сначала посмотреть логи**. На странице «Containers» кликните целевой контейнер и выберите «Logs» — увидите realtime-вывод: есть фильтры по последнему дню, 4 часам, 1 часу, 10 минутам, и можно включить «Trace» для живого обновления. Логи — это монолог приложения в реальном времени: оно скажет «я ищу базу и не нахожу» или «мне не хватает переменной окружения» — куда точнее ваших догадок. У 90% проблем ответы уже в логах.

## Персистентность данных: Volume-маунты

Сяомин засомневался: «А если удалить контейнер — данные пропадут?»

Ответ: **если настроены Volume-маунты, данные не теряются**.

Старожил объяснил: «Контейнер — как временное рабочее место: уходя, его очищают. Но Volume — ваш **персональный картотечный шкаф**: сколько бы раз вы ни меняли рабочие места, содержимое шкафа остаётся при вас».

Приложения, установленные 1Panel, по умолчанию сконфигурированы с Volume, данные лежат в каталоге `/opt/1panel/` сервера. Просмотреть и управлять всеми Volume можно на странице «Containers - Volumes». Поэтому контейнеры можно спокойно удалять и пересоздавать — данные не потеряются.

Сяомин попробовал: остановил контейнер PostgreSQL, запустил снова — данные в базе на месте. «Как сменить рабочее место, а картотека не переезжала».

```bash
# Посмотреть все Volume
docker volume ls

# Детали конкретного Volume
docker volume inspect 1panel-postgresql-data
```

::: warning Бэкап Volume — настоящая страховка
Хотя Volume не теряются при удалении контейнера, при поломке диска сервера данные всё равно исчезнут. Регулярный бэкап Volume на локальное или облачное хранилище — вот настоящая страховка. В 1Panel есть scheduled tasks для автоматических бэкапов.
:::

## Основы container networking

Здесь новички чаще всего наступают на грабли. Сяомин вписал `localhost` в `DATABASE_URL` — и подключение упало с ошибкой `Connection refused`: выглядело, будто база не стартует, но база явно работала.

Ключевое правило: **`localhost` в контейнере указывает на сам контейнер, а не на хост сервера**.

Когда вы зовёте «Мама!» дома — отвечает ваша мама. Когда зовёте «Мама!» в гостях у друга — отвечает мама друга. `localhost` в контейнере так же: `localhost` каждого контейнера — это он сам, а не хост сервера.

<ContainerNetwork />

| Сценарий | Адрес подключения | Причина |
|----------|-------------------|--------|
| Контейнер A к контейнеру B | Использовать **имя контейнера** (например, `1Panel-postgresql-ukow`) | Внутри одной Docker-сети имя контейнера — это hostname |
| Хост сервера к контейнеру | Использовать `127.0.0.1` или `localhost` | Порт контейнера замаплен на хост |
| Внешний браузер | Использовать **публичный IP сервера** + замапленный порт | Проходит через port mapping |

::: tip Конвенция имён контейнеров 1Panel
Контейнеры баз, созданные 1Panel, следуют формату `1Panel-{тип_базы}-{4_случайных_буквы}`:
- `1Panel-postgresql-ukow`
- `1Panel-redis-w94p`
- `1Panel-mysql-abcd`

Фактические имена контейнеров смотрите на странице «Containers».
:::

Сяомин поменял `localhost` в `.env` на `1Panel-postgresql-ukow` (фактическое имя контейнера PostgreSQL), рестартнул приложение — подключение прошло. «Так это всего одно слово». Он вздохнул: грабли маленькие, но без этого знания можно застрять на полдня.

Например: ваше Node.js-приложение работает в контейнере, и PostgreSQL тоже в контейнере. При настройке `DATABASE_URL` в `.env`:

```bash
# Правильно: фактическое имя контейнера, созданного 1Panel
DATABASE_URL="postgresql://username:password@1Panel-postgresql-ukow:5432/database_name"

# Неправильно: localhost (localhost в контейнере — это сам контейнер, базу не найдёт)
DATABASE_URL="postgresql://username:password@localhost:5432/database_name"
```

**Пример подключения Redis**:

```bash
# С паролем (обратите внимание: после : идёт пароль)
REDIS_URL="redis://:your_password@1Panel-redis-w94p:6379"

# Без пароля
REDIS_URL="redis://1Panel-redis-w94p:6379"
```

::: tip Как узнать имя и пароль юзера базы?
На странице «Database» в 1Panel кликните «Details» или «Connection Info» у нужной базы:
- Имя юзера (может быть `postgres`, `root` или ваше кастомное)
- Пароль (заданный при установке)
- Имя контейнера (также видно на странице «Containers»)
:::

::: warning Эти грабли сожгут вам часы
Неверно указанный адрес подключения — причина №1 провалов деплоя у новичков. Ошибки обычно выглядят как `Connection refused` или `ECONNREFUSED`, будто база не запущена, а на деле — просто неверный адрес. Запомните: **контейнеры ищут соседей по имени, хост находит контейнеры через localhost**.
:::
