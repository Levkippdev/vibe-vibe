# 14.3.2 Деплой Next.js-приложений

> **Цель раздела**: с помощью фичи runtime-окружения 1Panel задеплоить Next.js-проект на сервер и успешно получить к нему доступ.

Сяомин открыл страницу настройки runtime-окружений 1Panel и увидел, что полей не так много: «Проще, чем Vercel?»

Старый мастер сказал: «Примерно так. Деплой на своём сервере значит вручную пройти то, что Vercel делает за вас — просто заполнить несколько ключевых полей».

## Пререквизиты

Убедитесь, что вы:

- Поставили 1Panel на сервер (см. [14.2](./02-vps-setup.md))
- Поставили через магазин **OpenResty** и **PostgreSQL** (если проекту нужна база)
- Запушили код проекта на GitHub

## Шаг 1: Загрузка кода на сервер

Для создания runtime-окружения нужно указать «Project Directory», поэтому сначала загрузите код проекта на сервер. Частые способы:

- **Git Clone**: SSH на сервер и `git clone` репозитория в назначенный каталог
- **Файловый менеджер 1Panel**: через «Files» панели загрузить zip-архив и распаковать

```bash
# После SSH-логина клонируем код в назначенный каталог
cd /opt
git clone https://github.com/your-username/your-project.git

# Входим в каталог проекта и сначала ставим зависимости
cd your-project
pnpm install
```

Для приватных репозиториев понадобится настроить учётные данные GitHub (Personal Access Token) или SSH-ключ.

::: tip Публичные репозитории проще
Если проект не содержит чувствительной информации (ей место в переменных окружения, а не в коде), сделайте репозиторий Public — и шаги настройки учётных данных не понадобятся.
:::

## Шаг 2: Понимание port mapping

Перед созданием runtime-окружения разберём ключевую концепцию: **port mapping**.

Ваше Next.js-приложение работает внутри Docker-контейнера и по умолчанию слушает порт 3000. Но контейнеры изолированы: когда внешние юзеры обращаются к IP сервера, они не достучатся до порта 3000 внутри контейнера. Нужно настроить **port mapping**: открыть внешний порт на сервере и форвардить трафик на порт 3000 в контейнере.

```
Юзер заходит → ServerIP:3001 → Форвард на → Внутри контейнера:3000 → Next.js app
```

::: tip Что такое port mapping?
У здания один адрес, но много комнат. У сервера один IP, а разные порты — это разные приложения: комната 3001 — ваш сайт, комната 3002 — API, комната 5432 — база. Port mapping соединяет внешний номер комнаты (внешний порт) с внутренним номером (порт контейнера).
:::

Сяомин слегка запутался: «То есть мне нужно заполнить два порта?» Старый мастер: «Да. Внутренний порт контейнера — 3000 (дефолт Next.js), а внешний порт сервера выбирайте сами, например 3001. Юзеры заходят на 3001 — трафик форвардится на порт 3000 в контейнере».

## Пререквизит: решение проблемы нехватки памяти

Если у VPS всего 1–2GB памяти, при сборке Next.js-проекта вы можете словить out-of-memory (`JavaScript heap out of memory`). Решение — создать Swap-раздел (виртуальную память):

```bash
# Создаём swap-файл 2GB
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# Автомаунт при загрузке
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# Проверяем, что Swap активен
free -h
```

Создав Swap, даже при нехватке физической памяти система задействует диск и избежит провала сборки.

::: tip Когда нужен Swap?
- 1GB памяти: настоятельно рекомендуется создать 2GB Swap
- 2GB памяти: рекомендуется 1–2GB Swap
- 4GB и выше: обычно не нужен
:::

## Шаг 3: Создание runtime-окружения

::: tip Что такое runtime-окружение?
«Runtime Environment» 1Panel — по сути Docker-контейнер. Поля, которые вы заполняете в форме — каталог проекта, команда запуска, port mapping — становятся параметрами `docker-compose.yml`. Поняв это, дальнейшая конфигурация будет не такой пугающей.
:::

В панели 1Panel пройдите в «Websites > Runtime Environments» и кликните «Create Runtime Environment». Форма делится на базовую и расширенную секции.

**Базовая конфигурация** (ключевое внимание):

- **Name**: имя runtime-окружения (например, `my-nextjs-app`)
- **Project Directory**: путь, где лежит код (справа иконка папки для визуального выбора)
- **Version**: версия Node.js, по умолчанию свежая — обычно менять не нужно. Если локально вы на конкретной версии, выберите ту же
- **Startup Command**: `git pull && pnpm build && pnpm start` (объяснение ниже)
- **Container Name**: по умолчанию совпадает с именем окружения; используется для коммуникации контейнер-контейнер — когда backend-контейнеры подключаются к базам, они находят друг друга по имени контейнера

**Расширенная конфигурация** (видна после разворачивания):

- **Port Mapping**: замапить 3000 контейнера на 3001 сервера (объяснение ниже)
- **Environment Variables**: добавить переменные из `.env` по одной (объяснение ниже)

![image-20260302235637992](/images/Advanced/image-20260302235637992.png)

### Как настроить port mapping

При создании runtime-окружения разверните секцию «Advanced Configuration» и найдите область port mapping:

1. Кликните «Add», чтобы создать новую строку маппинга
2. **Host Port** — введите `3001` (внешний порт сервера, на ваше усмотрение)
3. **Container Port** — введите `3000` (дефолт Next.js)

```
Внешний порт сервера 3001  →  Внутренний порт контейнера 3000
```

Теперь юзеры, заходя на `http://ServerIP:3001`, попадают на порт 3000 внутри контейнера — ваше Next.js-приложение. Если проекту нужно открыть несколько портов, продолжайте кликать «Add» для новых маппингов.

После настройки не забудьте **открыть соответствующий внешний порт** (например, 3001) в security group провайдера.

![image-20260303151929448](/images/Advanced/image-20260303151929448.png)

### Как заполнить startup command

Это самое критичное поле всей формы. 1Panel даёт два режима:

- **Режим автопарсинга** (дефолт): 1Panel читает `package.json` проекта, парсит команды из `scripts` (например, `dev`, `build`, `start`) и показывает их в dropdown для выбора
- **Кастомный режим**: включите тумблер «Custom Startup Command» и вручную введите любую команду. Подходит для сценариев с несколькими последовательными шагами

Для Next.js-проектов `pnpm start` — только запуск: он требует, чтобы проект уже был собран. Поэтому рекомендуется кастомный режим, сцепляющий пуллинг кода, сборку и запуск:

```bash
git pull && pnpm build && pnpm start
```

Так каждый рестарт автоматически подтягивает свежий код и пересобирает. Для обновления деплоя достаточно кликнуть «Restart» в панели — не нужно вручную SSH на сервер.

Установку зависимостей (`pnpm install`) рекомендуется сделать по SSH после загрузки кода (как в шаге 1), а не включать в startup command — переустановка зависимостей при каждом рестарте медленная и излишняя. Если позже добавите новые зависимости, просто один раз выполните `pnpm install` по SSH.

Сяомин засомневался на «Startup Command»: локально он использовал `pnpm dev`, но в продакшене нужен `pnpm start`. Старый мастер напомнил: «dev — dev-режим с hot reload и дебаг-инструментами, производительность слабая и небезопасно. В продакшене всегда start».

### Как заполнить переменные окружения

::: tip Безопасное управление переменными окружения
Переменные окружения часто содержат чувствительное (пароли базы, API-ключи). О безопасном управлении этими секретами — глава 8 «Аутентификация и security», раздел «Переменные окружения и управление секретами».
:::

Область переменных окружения в форме — список key-value: в каждой строке «Key» и «Value», клик «Add» создаёт новую строку, красная иконка корзины удаляет. Добавьте переменные из вашего локального `.env`:

```bash
# Подключение к PostgreSQL (hostname — имя контейнера!)
DATABASE_URL="postgresql://username:password@1Panel-postgresql-xxxx:5432/database_name"

# Подключение к Redis (если используете Redis)
# С паролем
REDIS_URL="redis://:your_password@1Panel-redis-xxxx:6379"
# Без пароля
REDIS_URL="redis://1Panel-redis-xxxx:6379"

# Остальные переменные окружения
BETTER_AUTH_SECRET="your_secret_key"
BETTER_AUTH_URL="http://your_ip:port"
NODE_ENV="production"
```

::: warning Конвенция имён контейнеров
Контейнеры баз, созданные 1Panel, следуют формату `1Panel-{тип_базы}-{4_случайных_буквы}`:
- PostgreSQL: `1Panel-postgresql-ukow` (последние 4 случайны)
- Redis: `1Panel-redis-w94p` (последние 4 случайны)
- MySQL: `1Panel-mysql-abcd` (последние 4 случайны)

Фактические имена смотрите на странице «Containers», либо задавайте кастомные имена при создании баз.
:::

::: tip Формат connection string Redis
Формат строки подключения Redis зависит от того, задан ли пароль:
- **С паролем**: `redis://:password@container_name:6379` (обратите внимание: после `:` идёт пароль)
- **Без пароля**: `redis://container_name:6379` (просто опустите часть с паролем)
- **Указать базу**: `redis://container_name:6379/0` (хвостовое `/0` — использовать database 0)
:::

### Кликните Confirm и дождитесь запуска

Заполнив все конфигурации, кликните «Confirm». 1Panel выполнит пуллинг кода, сборку и запуск согласно вашей startup command. Первый старт будет медленнее: сборка Next.js может занять несколько минут — всё-таки на сервере лишь 2GB памяти.

Сяомин кликнул подтверждение, логи пошли скроллиться — пуллинг кода, сборка, запуск; почти две минуты — и наконец статус стал зелёным «Running».

Чтобы посмотреть runtime-логи, кликните кнопку «Logs» у нужного окружения в списке «Websites > Runtime Environments».

![image-20260302235748925](/images/Advanced/image-20260302235748925.png)

## Шаг 4: Доступ к приложению

После успешного старта приложения введите `http://ServerIP:3001` (ваш настроенный внешний порт) в браузере — и увидите своё приложение.

Сяомин ввёл адрес и увидел страницу своего приложения: «Оно правда работает на моём собственном сервере!» Он попробовал зарегистрировать аккаунт, запостить данные, рефрешнул страницу — данные на месте. Frontend, backend, база — все три части работают вместе на его собственном сервере.



## Имя контейнера vs localhost: подключения к базе

Это самое error-prone место деплоя, стоит подчеркнуть ещё раз:

| Где работает ваш код | Что писать в DATABASE_URL |
|---------------------|----------------------------|
| В Docker-контейнере (runtime-окружение 1Panel) | Использовать **имя контейнера**, например `postgresql` |
| На хосте сервера (ручной запуск по SSH) | Использовать `localhost` или `127.0.0.1` |

Старый мастер сказал: «Запомните одну фразу — **контейнеры ищут соседей по имени, хост находит контейнеры через localhost**».

## Разбор частых проблем

| Симптом | Возможная причина | Решение |
|---------|---------------|----------|
| Мгновенный exit после старта | Нет переменных окружения | Проверьте логи, донастройте переменные |
| Страница не открывается | Порт не открыт в security group | Откройте порт в консоли провайдера |
| Провал подключения к базе | Неверный hostname | Замените localhost на имя контейнера |
| Провал сборки | Не хватает памяти или несовпадение версии Node | Создайте Swap (см. «Пререквизит» выше) либо выберите версию Node как локально |

## Обновление деплоя

После обновления кода не нужно проходить весь процесс заново. Поскольку в startup command уже есть `git pull`, достаточно кликнуть «Restart» в списке «Websites - Runtime Environments» — панель сама спулит свежий код, пересоберёт и перезапустит. Если нужен полный ребилд из-за проблем, можно «Rebuild» приложение на странице «Installed» — панель удалит контейнер и пересоздаст его по текущей конфигурации, персистентные данные сохранятся.

Когда Сяомин впервые обновлял код, он по-простоте собирался SSH-нуться и сделать всё вручную. Старый мастер: «В startup command уже есть `git pull` — просто кликни «Restart» в панели. По SSH заходи, только если добавил новые зависимости — один раз прогони `pnpm install`». Весь процесс занял меньше минуты, и новая версия вышла в свет.

::: tip А если деплой упал?
Если rebuild или рестарт не поднимает приложение, первым делом смотрите логи — кнопка «Logs» в списке «Websites - Runtime Environments». Самые частые причины: новый код принёс новые переменные окружения, не настроенные в панели, или конфликт версий зависимостей. В логах обычно есть чёткое сообщение об ошибке.
:::
