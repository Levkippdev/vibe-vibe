# 14.3.3 Деплой статических сайтов

> **Цель раздела**: с помощью OpenResty в 1Panel задеплоить чисто frontend статический сайт.

Задеплоив Next.js-приложение, Сяомин вспомнил, что у него ещё есть документация на VitePress. «Её тоже можно на сервер?»

Опытный админ сказал: «Можно, но обычно нужды нет. Статике лучше всего живётся на Vercel или Cloudflare Pages — глобальный CDN, деплой по пушу и нулевое обслуживание. Ваш VPS — одна машина на одном сетевом маршруте, по скорости и надёжности она не соревнуется. Но раз вы учитесь деплою — стоит попрактиковаться. Процесс куда проще, чем с Next.js».

## Что такое статический сайт?

Статический сайт — сайт, состоящий **только из HTML-, CSS- и JavaScript-файлов**. Ему не нужен backend-сервер для realtime-обработки запросов. Когда юзеры заходят, OpenResty просто отдаёт файлы прямо в браузер.

Частые типы статических сайтов:

- Сайты документации и блоги, сгенерированные VitePress / Astro / Hugo
- Результат сборки React / Vue SPA (single-page applications)
- Чисто HTML лендинги и портфолио

Сайт документации Сяомина на VitePress всё это время хостился на Vercel, где и скорость доступа, и автодеплой были отличны. Но раз сервер уже работал, он хотел поставить туда и докс-сайт — в основном для практики и чтобы по пути ощутить полный воркфлоу деплоя.

Преимущества статических сайтов: они **быстрые, лёгкие и почти никогда не падают**. Runtime Node.js не нужен — одного OpenResty достаточно.

## Шаг 1: Локальная сборка

На компьютере сначала соберите проект в статические файлы:

```bash
# VitePress
pnpm build    # вывод в .vitepress/dist/

# Next.js (static export)
pnpm build    # требуется output: 'export' в next.config.js
              # вывод в out/

# Vite / React / Vue
pnpm build    # вывод в dist/
```

После сборки вы получите папку (`dist/`, `out/` или `.vitepress/dist/`) со всеми файлами, которые нужно загрузить на сервер.

Прогнав локально build-команду, Сяомин увидел, что папка `dist` заполнена HTML-, CSS- и JS-файлами. Он открыл один HTML — сплошной минифицированный код, совсем не похожий на исходники. «Так вот что такое build output — то, что браузер может запустить напрямую».

«И всё? Node.js гонять не нужно?» — «Именно. Статический сайт — просто пачка файлов, а OpenResty отдаёт их браузеру».

## Шаг 2: Создание сайта в 1Panel

Перейдите на страницу «Website» в 1Panel, кликните «Create Website» и выберите «Static Website». Введите основной домен (или сначала потестируйте с IP), оставьте остальное по дефолту и кликните подтверждение.
![1Panel static website creation settings page](/images/Advanced/14-vps-ops-deploy/14-3-3-static-site-01.png)

На странице «Website» в 1Panel Сяомин кликнул «Create Website», выбрал «Static Website», ввёл домен — и всё. 1Panel автоматически создал каталог сайта и сгенерировал конфиг OpenResty: руками конфиги писать не пришлось.

## Шаг 3: Загрузка build output

После создания сайта 1Panel сгенерирует корневой каталог сайта (например, `/opt/1panel/www/sites/your-domain/index/`).

На странице «Files» в 1Panel перейдите в корневой каталог сайта, загрузите архив с результатом сборки и распакуйте его.


Загрузка завершена — зайдите на сайт в браузере, и страница откроется мгновенно: статические сайты готовы к просмотру сразу после загрузки файлов, без ожидания сборки и запуска.

## Дополнительно: SPA-роутинг и кэширование (в большинстве случаев не требуется)

::: info Что такое SPA?
SPA (Single Page Application) — паттерн сборки у фреймворков вроде React / Vue: весь сайт состоит из одного `index.html`, а переключение страниц управляется frontend-JavaScript вместо реальной загрузки новых HTML-файлов. VitePress, Astro и Hugo генерируют настоящее многостраничное статическое HTML, поэтому они — **не SPA**.
:::

::: tip Как понять, что ваш проект — SPA?

**Быстрая проверка**:
1. Проверьте, есть ли в `package.json` скрипт `build`
2. Запустите `npm run build` (или `pnpm build`) и осмотрите результат:
   - Один `index.html` плюс пачка JS/CSS-файлов → **это SPA**
   - Много HTML-файлов (например, `about.html`, `contact.html`) → **не SPA**

**Частые SPA-фреймворки**:
- React (созданный через Vite или Create React App)
- Vue (созданный через Vite или Vue CLI)
- Angular

**Не SPA**:
- Традиционные многостраничные сайты (по одному HTML на страницу)
- Статические экспорты из SSR-фреймворков (Next.js, Nuxt)

Если не уверены — скорее всего, это не SPA, и настройку роутинга из этого раздела можно пропустить.
:::

### Фикс SPA-роутинга

Задеплоив SPA, вы наткнётесь на частую проблему: главная открывается нормально, но рефреш любой другой страницы отдаёт 404. Причина: когда юзер заходит на `/about`, OpenResty пытается найти `about.html`, но весь контент SPA на самом деле живёт внутри `index.html`.

Решение: в настройках сайта откройте страницу «Basic», найдите вкладку «Pseudo-static» в левой панели и введите:

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

Затем кликните «Save and Reload».

::: tip Пресеты правил pseudo-static
В dropdown «Scheme» есть пресеты rewrite-правил для PHP-фреймворков вроде WordPress и Laravel, но для Vue / React пресетов нет — правило выше нужно ввести вручную.
:::


### Стратегия кэширования SPA

Статические ассеты SPA (CSS, JS, картинки) меняются редко, поэтому включение кэширования даёт мгновенные загрузки при повторных визитах. В настройках сайта откройте вкладку «Configuration File» и добавьте внутри блока `server`:

```nginx
location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff2?)$ {
    expires 30d;
    add_header Cache-Control "public, immutable";
}
```

::: warning Юзеры видят старую версию после обновления?
Современные фронтенд-сборщики (Vite, Webpack) добавляют хеш в имена файлов (например, `app.a1b2c3.js`). При изменении контента в новой сборке хеш меняется, и браузер автоматически запросит новый файл. Так что долгий кэш безопасен — проблемы «юзеры застряли на старой версии» не будет.
:::

## Обновление статического сайта

В отличие от Next.js, у статических сайтов нет кнопки «Redeploy». Процесс обновления: пересобрать локально → загрузить новые файлы поверх старых. Если ручная загрузка каждый раз утомляет, можно написать простой скрипт для автоматизации или использовать GitHub Actions для автосборки и загрузки при пуше кода (см. CI/CD в главе 12).

## Частый траблшутинг

| Симптом | Возможная причина | Решение |
|------|---------|---------|
| Визит по домену — 404 | Сайт не создан или домен не привязан | Проверьте, есть ли соответствующий сайт в списке «Website» |
| Пустая страница | Неверный путь загрузки файлов | Убедитесь, что загрузили содержимое `dist`, а не саму папку `dist` |
| Рефреш страницы — 404 (SPA) | Нет конфигурации route fallback | Добавьте правило `try_files` в конфиг сайта (см. выше) |
| Стили/картинки не грузятся | Неверный base path при сборке | Проверьте настройку `base` в `vite.config.ts` или `next.config.js` |
| Security group открыта, а сайт всё равно недоступен | Порт 80 не разрешён в firewall 1Panel | Добавьте правило для порта 80 в «System → Firewall» |
| Файлы загружены, но изменения не видны | Кэш браузера | Hard refresh (Ctrl+Shift+R) или очистите кэш |

::: tip Приёмы дебага
1. **Смотрите логи OpenResty**: access-лог и error-лог в «App Store → Installed → OpenResty»
2. **Проверьте права на файлы**: загруженные файлы должны быть читаемы (1Panel обычно разруливает это автоматически)
3. **Используйте devtools браузера**: F12 → панель Network — видно, какие ресурсы не загрузились
:::
