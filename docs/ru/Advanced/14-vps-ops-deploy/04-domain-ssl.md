# 14.4 Настройка домена и сертификата

> **Цель раздела**: направить домен на сервер, получить бесплатный SSL-сертификат и дать юзерам безопасный доступ через `https://yourdomain.com`.

Приложение Сяомина работает, но `http://IP:3001` выглядит некрасиво. Он вспомнил главу 13 про привязку домена: «В этот раз A-запись на IP VPS, а не CNAME на платформу».

Опытный ментор сказал: «Привязка домена требует двух вещей, обе обязательны: **DNS помогает домену найти сервер, а создание сайта помогает серверу распознать домен**. Настроите только DNS без создания сайта — запрос дойдёт до сервера, но обрабатывать его некому; создадите сайт без DNS — юзеры вообще не найдут ваш сервер. В главе 13 CNAME работал как переадресация вызова: запрос форвардился на платформу, и она всё делала за вас. В этот раз A-запись — прямой набор: вы звоните на IP сервера напрямую, так что оба конца нужно настроить самому».

## Шаг 1: DNS A-записи — домен находит сервер

На странице управления DNS провайдера домена (Alibaba Cloud, Cloudflare или Tencent Cloud) добавьте **A-запись**. Цель шага — сообщить глобальной DNS-системе: «Этот домен соответствует этому IP».

| Тип записи | Host | Значение | TTL |
|---------|---------|-------|-----|
| A | `@` | Публичный IP вашего сервера | 600 |
| A | `www` | Публичный IP вашего сервера | 600 |

- `@` обозначает корневой домен (например, `yourdomain.com`)
- `www` обозначает `www.yourdomain.com`

Сяомин открыл страницу управления DNS регистратора и добавил две A-записи по таблице. Сама операция простая: выбрал тип, вписал host, вписал IP — готово за секунды. Но его всё ещё немного томило: «И всё? Домен правда будет указывать на мой сервер?»

![Tencent Cloud DNS configuration - @ record](/images/Advanced/14-vps-ops-deploy/14-4-dns-root-01.png)

![Tencent Cloud DNS configuration - www record](/images/Advanced/14-vps-ops-deploy/14-4-dns-www-02.png)

::: tip Распространение DNS занимает время
После добавления записей на вступление в силу уходит от нескольких минут до нескольких часов (зависит от настройки TTL и DNS-кэшей в разных локациях). Проверить можно командами:

```bash
# На вашем компьютере
nslookup yourdomain.com
# или
ping yourdomain.com
# или (подробнее)
dig yourdomain.com
```

Если возвращается IP вашего сервера — DNS уже вступил в силу.

**Если через 24 часа всё ещё не работает**:
1. Проверьте корректность DNS-записей (host, значение)
2. Убедитесь, что домен в нормальном статусе (не истёк, не залочен)
3. Попробуйте почистить локальный DNS-кэш: `ipconfig /flushdns` (Windows) или `sudo dscacheutil -flushcache` (Mac)
:::

## Шаг 2: Создание сайта — сервер распознаёт домен

DNS решает проблему «домен находит сервер», но получив запрос, сервер должен знать, куда его отправить. Создание сайта в 1Panel (что вы уже делали в прошлых разделах) и заполнение основного домена говорят OpenResty: «Когда придёт запрос для этого домена — отдай его мне».

Если домен уже введён при создании сайта в [14.3.2](./03-2-deploy-nextjs.md) или [14.3.3](./03-3-deploy-static.md), шаг уже сделан. Если тогда вы тестировали по IP, зайдите на страницу «Website» в 1Panel, отредактируйте соответствующий сайт и добавьте домен.

Убедитесь, что OpenResty установлен из магазина приложений.
![1Panel App Store - OpenResty](/images/Advanced/14-vps-ops-deploy/14-4-openresty-03.png)



После конфигурации убедитесь, что security group открыла порты **80** (HTTP) и **443** (HTTPS). Затем зайдите на `http://yourdomain.com` в браузере. Если видите свой сайт — конфигурация домена успешна.

Добавив A-записи, Сяомин не выдержал и вбил домен в браузер — но страница не загрузилась. Он подумал, что настроил что-то не так, но ментор сказал подождать: «DNS не вступает в силу мгновенно. DNS-серверам в разных регионах нужно время на синк». Через несколько минут он попробовал снова — страница появилась. Проверил и с телефона — открылось. «У моего сайта наконец есть собственный домен, а не просто строка из IP и порта».

## Шаг 3: Заявка на бесплатный SSL-сертификат Let's Encrypt

Сейчас сайт работает на HTTP, и браузер показывает предупреждение «Not Secure». Нужен SSL-сертификат для включения HTTPS.

Сяомин вспомнил, что при деплое на Vercel один `vercel deploy` делал всё: домен, HTTPS, CDN — всё настраивалось автоматически. Теперь на VPS каждый шаг вручную. «Такова цена своего сервера — но это и цена свободы».

В 1Panel пройдите в «Website > Certificate» и кликните «Apply for Certificate». Введите домен, выберите **HTTP verification** как способ валидации (простейший вариант, лишь бы порт 80 был доступен), включите «Auto Renew» и кликните подтверждение. Аккаунт ACME можно оставить дефолтным — «Automatically generated by 1Panel».

![Browser "Not Secure" warning](/images/Advanced/14-vps-ops-deploy/14-4-http-insecure-05.png)

![1Panel SSL certificate application configuration](/images/Advanced/14-vps-ops-deploy/14-4-ssl-apply-06.png)

![HTTP verification configuration](/images/Advanced/14-vps-ops-deploy/14-4-ssl-http-verify-07.png)

Подождите секунд пятнадцать. Когда статус сменится на «Issued», вернитесь на страницу настройки сайта, выберите только что полученный сертификат в настройках HTTPS и включите его.

::: tip Что такое Let's Encrypt?
Как рассказывалось в главе 13, Let's Encrypt — бесплатный автоматизированный центр сертификации, которым пользуются сотни миллионов сайтов по всему миру. Сертификаты валидны 90 дней, но продлеваются автоматически. Отличие от главы 13: там сертификатом управляла платформа, а теперь он живёт на вашем собственном сервере.
:::

Сяомин кликнул «Apply for Certificate» на странице «Website > Certificate», ввёл домен, выбрал HTTP-верификацию, включил автопродление и подтвердил. Секунд через пятнадцать статус стал «Issued». Он вернулся в настройки сайта, включил HTTPS, выбрал свежий сертификат и рефрешнул сайт — адресная строка сменилась с «Not Secure» на замочек. «Тот же зелёный замок, как в главе 13, только теперь сертификат на моём собственном сервере».

## Шаг 4: Принудительный HTTPS-редирект

После включения HTTPS сайт поддерживает и HTTP, и HTTPS. Но мы хотим, чтобы все HTTP-запросы автоматически редиректились на HTTPS.

На странице настроек HTTPS сайта в 1Panel найдите «HTTP Options» и выберите «**Automatically redirect HTTP access to HTTPS**».

::: tip Разбор HTTP-опций
1Panel даёт три HTTP-опции:
- **Automatically redirect HTTP access to HTTPS**: рекомендуемая. Все HTTP-запросы автоматически редиректятся на HTTPS
- **Direct HTTP access allowed**: доступны и HTTP, и HTTPS, без принудительного редиректа
- **Disable HTTP**: разрешён только HTTPS, HTTP-запросы отклоняются сразу
:::


После включения юзеры, заходя на `http://yourdomain.com`, автоматически попадут на `https://yourdomain.com` — и в адресной строке появится замочек.

Сяомин нарочно вбил в браузер URL с `http://`. После Enter — автоматический редирект на `https://`. Он попробовал и адрес без `www` — редирект тоже отработал. «Теперь работает любой вход. Как бы юзеры ни набирали, попадут на шифрованное безопасное соединение».

## Шаг 5: Автопродление сертификата

Сертификат Let's Encrypt валиден только 90 дней. Если сертификат истечёт, юзеры при открытии сайта увидят полноэкранное красное предупреждение браузера «Your connection is not private» — и большинство просто закроет страницу. К счастью, если при заявке вы включили «Auto Renew», 1Panel **продлит его автоматически** до истечения (и HTTP-верификация, и DNS-аккаунт поддерживают автопродление). Также можно триггернуть продление вручную кнопкой «Apply» в списке сертификатов.

::: warning Частые причины провала продления

1. **Порт 80 занят или заблокирован**: HTTP-верификации Let's Encrypt нужен доступ к порту 80
2. **Изменился DNS**: домен больше не указывает на этот сервер
3. **Изменились правила firewall**: security group закрыла порт 80

При провале автопродления 1Panel покажет алерт в панели. Просто кликните «Apply» в списке сертификатов для ретрая.
:::

## Мультидомены и wildcard-сертификаты

Если у вас несколько поддоменов (например, `api.yourdomain.com` и `docs.yourdomain.com`), для каждого нужен отдельный сертификат. Wildcard-сертификат разом покрывает все поддомены:

**Вариант 1: Отдельный сертификат на каждый поддомен**

Простейший путь. Каждый сайт независимо управляет своим сертификатом.

**Вариант 2: Wildcard-сертификат**

Один сертификат покрывает все поддомены `*.yourdomain.com`. Потребуется **DNS-верификация** (вместо HTTP):

1. В «Website > Certificate > DNS Account» добавьте API-ключ провайдера домена (например, Alibaba Cloud AccessKey или Cloudflare API Token)

::: details Как получить API-ключ у DNS-провайдера?

**Alibaba Cloud**:
1. Залогиньтесь в консоль Alibaba Cloud
2. Аватар справа вверху → AccessKey Management
3. Создайте AccessKey (AccessKey ID + AccessKey Secret)
4. Внесите оба значения в 1Panel

**Cloudflare**:
1. Залогиньтесь в Cloudflare Dashboard
2. Аватар справа вверху → My Profile → API Tokens
3. Создайте Token по шаблону «Edit zone DNS»
4. Внесите Token в 1Panel

**Tencent Cloud**:
1. Залогиньтесь в консоль Tencent Cloud
2. Аватар справа вверху → Access Management → API Key Management
3. Создайте ключ (SecretId + SecretKey)
4. Внесите оба значения в 1Panel

:::

![Configure DNS account](/images/Advanced/14-vps-ops-deploy/14-4-ssl-success-08.png)

2. При заявке на сертификат введите `*.yourdomain.com` как домен, выберите «DNS verification» способом валидации и укажите только что добавленный DNS-аккаунт

![Apply for a wildcard certificate](/images/Advanced/14-vps-ops-deploy/14-4-https-enable-09.png)

3. 1Panel автоматически добавит TXT-запись у провайдера домена для завершения верификации. Просто дождитесь выдачи

| Тип сертификата | Покрытие | Способ валидации | Для кого |
|---------|---------|---------|---------|
| Single domain | `yourdomain.com` | HTTP / DNS — оба поддерживаются | Только один домен |
| Multi-domain | Несколько указанных доменов | HTTP / DNS — оба поддерживаются | 2–3 домена |
| Wildcard | `*.yourdomain.com` | Только DNS-верификация | Много поддоменов |
