## Введение

Skill — набор инструкций, упакованных в простую папку, который учит Claude обращаться с конкретными задачами или воркфлоу. Skills — один из мощнейших способов кастомизировать Claude под нужные задачи. Вместо перепрописывания своих предпочтений, процессов и доменной экспертизы в каждом разговоре skills позволяют обучить Claude один раз — и выигрывать каждый раз.

Skills особенно сильны при повторяемых воркфлоу: генерация frontend-дизайнов из спецификаций, исследования по консистентной методологии, создание документации по стайл-гайду команды или оркестрация многошаговых процессов. Они хорошо работают вместе со встроенными способностями Claude вроде исполнения кода и создания документов. Тем, кто строит MCP-интеграции, skills добавляют ещё один мощный слой, помогающий превращать сырой доступ к инструментам в надёжные, оптимизированные воркфлоу.

Этот гайд покрывает всё для построения эффективных skills — от планирования и структуры до тестирования и дистрибуции. Строите ли skill для себя, команды или комьюнити — найдёте практические паттерны и реальные руководства.

### Что вы узнаете

- Технические требования и best practices для структуры skill
- Паттерны для standalone-скиллов и MCP-усиленных воркфлоу
- Эффективные паттерны из разных кейсов
- Как тестировать, итерировать и дистрибутировать свои skills

### Для кого это

- Разработчики, желающие, чтобы Claude стабильно следовал конкретным воркфлоу
- Power-юзеры, желающие придерживаться определённых процессов
- Команды, стремящиеся стандартизировать работу Claude в организации

### Два пути в этом гайде

**Оценка времени:** Функциональный skill можно построить за одну сессию. Создание и тестирование первого работающего skill'а через skill-creator занимает примерно 15–30 минут.

## Основы

### Что такое Skill?

Skill — папка, содержащая:

- **SKILL.md** (обязательно): Markdown-инструкции с YAML frontmatter
- **scripts/** (опционально): исполняемый код (Python, Bash и т.д.)
- **references/** (опционально): документация, загружаемая по требованию
- **assets/** (опционально): шаблоны, шрифты, иконки для вывода

### Ключевые принципы дизайна

#### Прогрессивное раскрытие

Skills используют трёхуровневую систему:

- **Уровень 1 (YAML frontmatter):** Всегда загружается в системный промпт Claude. Достаточно информации, чтобы Claude знал, когда использовать skill — без загрузки всего в контекст.

- **Уровень 2 (тело SKILL.md):** Загружается, когда Claude определяет релевантность skill'а для текущей задачи. Содержит полные инструкции и руководство.

- **Уровень 3 (связанные файлы):** Дополнительные файлы в директории skill'а, к которым Claude может опционально обратиться и которые открываются только по необходимости.

Такое прогрессивное раскрытие минимизирует расход токенов, сохраняя доступность экспертизы.

#### Композируемость

Claude может загружать несколько skills одновременно. Ваш skill должен хорошо работать с другими, не предполагая, что он — единственная доступная способность.

#### Портативность

Skills работают одинаково на Claude.ai, Claude Code и API. Создайте skill один раз — и он работает на всех платформах без модификаций (при условии, что окружение поддерживает зависимости skill'а).

### Для строителей MCP: Skills + коннекторы

Если вы строите standalone-скиллы без MCP — переходите к Планированию и дизайну; сюда можно вернуться позже.

В комбинации с MCP skills превращаются из документов-инструкций в оркестраторы воркфлоу. Где MCP даёт *инструменты* (доступ к API, подключения к базам, операции с файлами), skills дают *интеллект* (когда использовать какой инструмент, в каком порядке, с какими параметрами и как обрабатывать edge cases).

**Паттерн синергии:**

| Компонент | Даёт | Пример |
| --- | --- | --- |
| MCP-сервер | Сырой доступ к инструментам | `create_issue()`, `query_database()` |
| Skill | Интеллект воркфлоу | «При создании баг-репорта сначала проверь дубликаты, затем собери системную информацию, затем создай с правильными лейблами» |
| Вместе | Надёжные автоматизированные воркфлоу | Баг-филинг одним промптом, консистентный каждый раз |

Skills решают частые боли MCP: неконсистентное использование инструментов, пропущенные шаги в воркфлоу, слабая обработка ошибок и необходимость юзеров помнить сложные последовательности. Они превращают «вот некоторые инструменты» в «вот экспертный ассистент».

## Планирование и дизайн

### Три категории Skills

Skills обычно попадают в три категории, каждая со своими паттернами дизайна:

#### Категория 1: Создание документов и ассетов

Skills, производящие консистентный высококачественный вывод — отчёты, презентации, дизайны или код. Ключевой вызов — поддержание качества и консистентности формата между использованиями.

**Паттерн дизайна:** Определите ясные спецификации вывода, включите примеры хорошего вывода, укажите критерии качества и постройте чекпоинты самооценки.

#### Категория 2: Автоматизация воркфлоу

Skills, оркестрирующие многошаговые процессы. Ключевой вызов — ветвящаяся логика, состояния ошибок и поддержание контекста между шагами.

**Паттерн дизайна:** Смаппируйте полный воркфлоу с точками решений, определите ясные критерии входа/выхода каждого шага, включите обработку ошибок на каждой стадии и сохраняйте состояние между шагами.

#### Категория 3: Усиление MCP

Skills, добавляющие интеллект воркфлоу поверх доступа к MCP-инструментам. Ключевой вызов — сделать использование инструментов надёжным и оптимизированным.

**Паттерн дизайна:** Задокументируйте оптимальную последовательность использования инструментов, включите частые паттерны восстановления после ошибок, определите гейты качества между шагами и дайте контекстно-осведомлённое руководство по выбору инструментов.

### Структура SKILL.md

Файл SKILL.md состоит из двух частей: YAML frontmatter и тело инструкций.

#### YAML Frontmatter

```yaml
---
name: skill-name-kebab-case
description: "[Что делает] + [Когда использовать] + [Ключевые фичи]"
license: MIT
compatibility:
  - "Requires Python 3.9+"
  - "Works with Claude.ai, Claude Code, API"
metadata:
  author: your-name
  version: "1.0.0"
---
```

**Критические правила:**

- `name` обязан быть kebab-case (строчные с дефисами)
- `description` обязан включать и *что*, и *когда* — Claude использует это для решения, когда загружать skill
- Никаких XML-угловых скобок в frontmatter
- Именование папок: только kebab-case
- Именование файла: ровно `SKILL.md` (чувствительно к регистру)
- Никакого `README.md` внутри папки skill'а

#### Тело инструкций

Тело идёт за frontmatter и содержит собственно инструкции для Claude. Ключевые принципы:

**Будьте конкретны и действенны.** Вместо «пиши хороший код» — «используй TypeScript strict mode, обрабатывай все ошибочные кейсы типизированными error-объектами и включай JSDoc для публичных API».

**Используйте примеры щедро.** Показывайте Claude, как выглядит хороший вывод. Один конкретный пример сообщает больше, чем абзацы описаний.

**Включайте деревья решений.** Когда skill обрабатывает несколько сценариев, делайте ветвящуюся логику явной: «Если юзер даёт ссылку Figma — начни с извлечения дизайна. Если текстовые требования — начни с генерации вайрфреймов».

**Определяйте критерии качества.** Фиксируйте, как выглядит «готово»: «Вывод завершён, когда у всех API-эндпоинтов есть соответствующие тест-файлы, каждый минимум с одним happy-path и одним ошибочным тестом».

## Тестирование и итерация

### Три измерения тестирования

#### 1. Тестирование триггеров

Проверьте, что skill загружается в правильное время — и не загружается, когда не должен.

- Тестируйте промптами, которые должны триггерить skill
- Тестируйте похожими, но нерелевантными промптами, которые НЕ должны его триггерить
- Убедитесь, что description во frontmatter достаточно специфична для избежания false positives

#### 2. Функциональное тестирование

Валидируйте, что skill производит корректный вывод.

- Тестируйте каждый основной путь воркфлоу
- Тестируйте edge cases и ошибочные сценарии
- Проверяйте, что формат вывода соответствует спецификациям
- Проверяйте, что критерии качества соблюдены

#### 3. Сравнение производительности

Докажите, что skill улучшает базовое поведение Claude.

- Прогоните ту же задачу с skill'ом и без
- Измеряйте качество, консистентность и уровень завершения
- Отслеживайте расход токенов и время ответа
- Документируйте конкретные улучшения

### Ключевые метрики успеха

- Триггерится на 90%+ релевантных запросов
- Завершает воркфлоу за X вызовов инструментов (задайте цель)
- Ноль проваленных API-вызовов на воркфлоу
- Не требует промптинга юзера для следующих шагов
- Консистентные результаты между сессиями

### Подход к итерации

Skills редко работают идеально с первой попытки. Цикл итерации:

1. **Протестируйте** skill репрезентативными промптами
2. **Выявите**, где Claude отклоняется от ожидаемого поведения
3. **Диагностируйте**, проблема ли в условиях триггера, инструкциях или примерах
4. **Уточните** конкретную секцию, вызывающую проблемы
5. **Перетестируйте** для проверки фикса и регрессий

Частые фиксы:
- Skill не триггерится → Улучшите поле `description` во frontmatter
- Skill триггерится слишком широко → Добавьте специфичности в description, включите руководство «не использовать, когда»
- Качество вывода нестабильно → Добавьте больше примеров, ужесточите критерии качества
- Шаги воркфлоу пропускаются → Сделайте переходы шагов явнее, добавьте чекпоинты

## Дистрибуция и шеринг

### Хостинг

Хостите skills на GitHub в публичном репозитории. Включите:
- Ясный README с целью и использованием skill'а
- Инструкции по установке
- Примеры промптов и ожидаемого вывода
- Историю версий

### Методы установки

**Индивидуальные юзеры:** Загрузка на Claude.ai через Settings > Skills.

**Развёртывание в организации:** Доступно с декабря 2025 для команд, нуждающихся в стандартизированных наборах skills по организации.

**Использование через API:** Skills можно загружать программно для автоматизированных воркфлоу.

**Claude Code:** Skills автоматически обнаруживаются из структуры директорий проекта.

### Когда использовать Skills против AGENTS.md — или оба

| Подход | Лучше всего для | Как работает |
| --- | --- | --- |
| **Skills** | Конкретные повторяемые воркфлоу | Загружаются по требованию при релевантности |
| **AGENTS.md** | Широкие конвенции и контекст проекта | Всегда присутствует в системном промпте |
| **Оба** | Сложные проекты и с конвенциями, и с воркфлоу | AGENTS.md для горизонтальных знаний, Skills для вертикальных воркфлоу |

Skills и AGENTS.md играют комплементарные роли. AGENTS.md даёт персистентный, всегда доступный контекст о проекте (тех-стек, конвенции кодинга, архитектурные решения). Skills дают экспертизу по требованию для конкретных задач (воркфлоу code review, процедуры деплоя, паттерны тестирования).

Для максимальной эффективности используйте AGENTS.md для информации, нужной агенту на каждой задаче, и Skills для специализированных воркфлоу, нужных только при конкретных операциях.

## Паттерны и траблшутинг

### Частые паттерны

**1. Оркестрация последовательного воркфлоу:** Линейная серия шагов, каждый строится на выводе предыдущего. Лучше всего для процессов с ясным потоком от начала до конца.

**2. Координация нескольких MCP:** Skills, оркестрирующие через несколько MCP-серверов, выбирая правильный инструмент с правильного сервера на каждом шаге. Существенно для сложных интеграций.

**3. Итеративные петли улучшения:** Skills с циклами самооценки и рафинирования. Skill инструктирует Claude оценивать вывод по критериям качества и итерировать до соответствия стандартам.

**4. Контекстно-осознанный выбор инструментов:** Skills, направляющие Claude к разным инструментам или подходам по текущему контексту — размер проекта, тех-стек, уровень экспертизы юзера и т.д.

**5. Домен-специфический интеллект:** Skills, встраивающие глубокие доменные знания для решений, которые generic-Claude не принял бы оптимально — например, знание, что определённые миграции базы всегда должны быть обратимыми, или что конкретные API-эндпоинты требуют rate limiting.

### Частые проблемы и решения

**Проблема: Skill никогда не триггерится**
Решение: Ревьюйте поле `description`. Оно должно ясно фиксировать, *когда* использовать skill, не только *что* он делает. Тестируйте разные формулировки промптов.

**Проблема: Claude игнорирует инструкции skill'а**
Решение: Инструкции могут быть слишком расплывчаты или противоречивы. Используйте конкретный, действенный язык. Проверьте конфликты с другими загруженными skills.

**Проблема: Вывод неконсистентен**
Решение: Добавьте больше примеров ожидаемого вывода. Ужесточите критерии качества. Включите шаг самооценки перед финальным выводом.

**Проблема: Расход токенов слишком высок**
Решение: Перенесите детальный справочный материал на уровень 3 (связанные файлы). Держите тело SKILL.md сфокусированным на логике ядра воркфлоу. Эффективно используйте прогрессивное раскрытие.

### Быстрая справка: технические требования

| Требование | Спецификация |
| --- | --- |
| Имя папки | только kebab-case |
| Обязательный файл | `SKILL.md` (точный регистр) |
