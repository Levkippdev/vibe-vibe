# React best practices: 10+ лет оптимизации производительности от Vercel

**Оригинал: [Introducing React Best Practices](https://vercel.com/blog/introducing-react-best-practices) (Shu Ding, Andrew Qu)**

## Зачем структурированный репозиторий практик?

Знания о производительности React и Next.js исторически были рассеяны по блог-постам, докладам, GitHub-issues и tribal knowledge внутри команд. Разработчику, оптимизирующему приложение, приходилось собирать советы из десятков источников, часто противоречивых или устаревших.

Репозиторий React Best Practices от Vercel меняет это. Он упаковывает больше десятилетия знаний об оптимизации в структурированный, машиночитаемый формат, который эффективно потребляют и люди, и AI-агенты. Ключевой инсайт: AI-кодинг-агентам нужны структурированные руководства — не рассеянные блог-посты — чтобы стабильно производить оптимизированный код.

## Структура репозитория

Репозиторий организован вокруг иерархии: **правила → примеры → тесты**.

Каждое правило следует консистентному формату:

- **Имя и ID правила**: Краткий идентификатор для ссылок (например, `eliminate-client-server-waterfalls`)
- **Описание**: Что покрывает правило и почему это важно
- **Плохой пример**: Код, нарушающий правило, с аннотациями проблемы
- **Хороший пример**: Исправленная версия с аннотациями улучшения
- **Импакт**: Ожидаемый рост производительности (квантифицированный, где возможно)
- **Референсы**: Ссылки на глубокие объяснения

Эта структура не только для читаемости людьми. Она спроектирована так, чтобы AI-агенты могли парсить правила, понимать паттерны и применять их при генерации и ревью кода.

## Ключевые области покрытия

40+ правил организованы в высокоимпактные категории:

### Устранение waterfalls

Waterfall-запросы — где fetching данных последовательный вместо параллельного — убийца производительности №1 в React-приложениях. Репозиторий покрывает:

- Идентификацию client-server waterfalls (монтирование компонента → fetch → монтирование дочернего → fetch)
- Server Components для переноса fetching'а на сервер
- Параллельный fetching с `Promise.all` и встроенной дедупликацией запросов React
- Прелоад данных паттернами `preload` для устранения последовательных fetch'ей
- Стриминг с Suspense для прогрессивного UI при загрузке данных

### Снижение bundle size

Меньше JavaScript напрямую улучшает Time to Interactive:

- Перенос компонентов в Server Components, когда интерактивность не нужна
- Динамические импорты с `next/dynamic` для тяжёлых клиентских компонентов
- Анализ и устранение неиспользуемых зависимостей
- Best practices tree-shaking'а и антипаттерны barrel-файлов
- Паттерны оптимизации шрифтов и изображений

### Оптимизация ре-рендеров

Лишние ре-рендеры жгут CPU и создают дёрганый UI:

- Паттерны композиции вместо `React.memo` (лифтинг стейта, children как props)
- Корректные массивы зависимостей хуков
- Colocation стейта — держать state рядом с местом использования
- Разделение контекста для предотвращения широких ре-рендеров
- Взвешенное использование `useMemo` и `useCallback` (не везде)

### Паттерны Server Components

React Server Components — крупнейший архитектурный сдвиг в истории React:

- Когда использовать Server против Client Components
- Граница `"use client"` и её следствия для дерева компонентов
- Передача серверных данных клиентским компонентам через props (не повторный fetching)
- Эффективная композиция Server и Client Components
- Избегание частых ошибок вроде импорта server-only модулей в клиентский код

### Стриминг и Suspense

Прогрессивная загрузка драматически улучшает воспринимаемую производительность:

- Обёртка медленных источников данных в Suspense-границы
- Паттерны loading UI (скелеты, спиннеры, прогрессивный контент)
- Вложенные Suspense для гранулярных состояний загрузки
- Error boundaries в паре с Suspense для устойчивых UI

## Интеграция с AI-агентами

Репозиторий спроектирован как AI-native источник знаний:

- **Skills для Claude Code**: Правила могут загружаться как Skill, давая Claude Code структурированное руководство по React-производительности при генерации и ревью кода.
- **Интеграция с AGENTS.md**: Команды могут ссылаться на конкретные правила в своих AGENTS.md, сообщая AI-агентам, какие оптимизации важнее для проекта.
- **Структура под RAG**: Консистентный формат правил делает репозиторий идеальным для retrieval-augmented generation, где AI-агенты подтягивают релевантные правила под пишущийся код.

Когда AI-агент имеет доступ к этим правилам, качество вывода измеримо растёт. Вместо React-кода, который «работает», он генерирует React-код, который работает *быстро*.

## Частые антипаттерны и фиксы

Примеры высокоимпактных правил:

**Антипаттерн**: Fetch данных в `useEffect` внутри клиентского компонента, вложенного на три уровня.
**Фикс**: Перенесите fetching в Server Component на уровне роута и передавайте данные вниз через props.

**Антипаттерн**: Barrel-файл (`index.ts`), ре-экспортирующий всё из большой библиотеки компонентов.
**Фикс**: Импортируйте напрямую из файла компонента для включения tree-shaking.

**Антипаттерн**: Оборачивание каждого компонента в `React.memo` как «оптимизация».
**Фикс**: Используйте паттерны композиции — перестройте дерево так, чтобы ре-рендеры не распространялись без нужды.

## Как внедрять инкрементально

Не нужно применять все 40+ правил разом. Репозиторий предлагает путь внедрения:

1. **Начните с waterfalls**: Максимальный импакт на производительность и проще всего измерять. Аудируйте network tab на цепочки последовательных запросов.
2. **Дальше bundle size**: Анализируйте build output. Найдите крупнейшие клиентские чанки и ищите возможности Server Components.
3. **Затем ре-рендеры**: Используйте React DevTools Profiler для поиска чрезмерно ре-рендерящихся компонентов.
4. **Внедряйте непрерывно**: Пишите новые фичи сразу по правилам. Ретрофитить сложнее, чем строить правильно.

Структурированный формат позволяет селективно загружать только релевантные текущей работе правила — waterfall-правила при строительстве data-heavy страниц, bundle-правила при оптимизации под мобилки, re-render-правила при построении интерактивных UI.

## Почему это важно

Производительность — не фича, а базовое ожидание. Юзеры уходят с медленных сайтов. Поисковики их штрафуют. А с AI-агентами, пишущими всё большую долю продакшн-кода, обеспечение доступа этих агентов к best practices производительности — не опция, а инфраструктура.

Репозиторий React Best Practices от Vercel превращает трудно добытые знания об оптимизации в переиспользуемый, AI-потребляемый актив. Хоть вы человек-разработчик в поисках руководства, хоть AI-агент, генерирующий код, — правила дают общий стандарт того, как выглядит «хороший React-код» в 2026-м.
