# React best practices: 10+ лет оптимизации производительности от Vercel

**Авторы: Shu Ding, Andrew Qu**

**Оригинал: [Introducing React Best Practices](https://vercel.com/blog/introducing-react-best-practices) (Shu Ding, Andrew Qu)**

Мы упаковали 10+ лет знаний об оптимизации React и Next.js в [`react-best-practices`](https://github.com/vercel-labs/agent-skills/tree/main/skills/react-best-practices) — структурированный репозиторий, оптимизированный для AI-агентов и LLM.

![React Best Practices](/images/articles/2026-01/react-best-practices-hero.png)

## Зачем нужен этот фреймворк

Работа по оптимизации React обычно реактивна: после релиза приложение замедляется, команда начинает выслеживать симптомы. Это дорого — и легко оптимизировать не в ту сторону.

Мы видели повторяющиеся root causes в продакшн-кодовых базах больше десятилетия:

- **Асинхронные операции неожиданно выполняются последовательно**
- **Клиентский bundle растёт со временем**
- **Компоненты ре-рендерятся без нужды**

Влияние этих проблем прямое: они проявляются как ожидание, лаги и повторяющиеся издержки в каждой юзерской сессии.

Поэтому мы собрали этот фреймворк практик — сделать проблемы легче находимыми и исправимыми.

## Ключевая идея: приоритизация

Большинство оптимизаций проваливаются, потому что стартуют с нижних слоёв стека.

Если waterfall-запросы добавляют 600ms ожидания, никакие трюки с `useMemo` не помогут. Если каждая страница отдаёт лишние 300KB JavaScript, экономия микросекунд в цикле бессмысленна.

Проблемы производительности также копятся: маленькая деградация, зас dunkая сегодня, становится долгосрочным «налогом» с каждой сессии — пока кто-то не выплатит долг.

Поэтому фреймворк начинается с двух фиксов, обычно сильнее всего двигающих реальные метрики:

1. **Устранение waterfalls**
2. **Снижение bundle size**

Затем переходят к серверной производительности, клиентскому fetching'у и оптимизации ре-рендеров.

Фреймворк содержит 40+ правил в 8 категориях, отсортированных по импакту — от CRITICAL (waterfalls, bundle size) до инкрементальных оптимизаций (advanced-паттерны).

## Что внутри фреймворка

Репозиторий покрывает восемь категорий производительности:

- **Устранение асинхронных waterfalls**
- **Оптимизация bundle size**
- **Серверная производительность**
- **Клиентский fetching данных**
- **Оптимизация ре-рендеров**
- **Рендер-производительность**
- **Advanced-паттерны**
- **JavaScript-производительность**

Каждое правило имеет рейтинг импакта (CRITICAL до LOW), помогающий приоритизировать фиксы, и code-примеры, показывающие проблему и решение.

Структура правил консистентна: **имя и ID** (например, `eliminate-client-server-waterfalls`), **описание**, **плохой пример** с аннотациями проблемы, **хороший пример** с аннотациями улучшения, **импакт** (квантифицированный, где возможно), **референсы**. Формат спроектирован и для читаемости людьми, и для парсинга AI-агентами.

### Пример: избегайте ненужного async-ожидания

Распространённый паттерн, блокирующий неиспользуемый код:

**Неправильно (обе ветки блокированы)**:

```typescript
async function handleRequest(userId: string, skipProcessing: boolean) {
  // даже при skipProcessing = true ждём userData
  const userData = await fetchUserData(userId)

  if (skipProcessing) {
    // возвращаем сразу — но уже дождались userData
    return { skipped: true }
  }

  // только эта ветка использует userData
  return processUserData(userData)
}
```

**Правильно (блокируемся только при необходимости)**:

```typescript
async function handleRequest(userId: string, skipProcessing: boolean) {
  if (skipProcessing) {
    // ранний возврат без ожидания данных
    return { skipped: true }
  }

  // фетчим только когда нужно
  const userData = await fetchUserData(userId)
  return processUserData(userData)
}
```

Отдельные файлы правил компилируются в `AGENTS.md` — единый документ, который ваш агент может консультировать при ревью кода или предложении оптимизаций. Он спроектирован для консистентного следования, включая AI-агентские рефакторинги, чтобы команда применяла одинаковые решения в больших кодовых базах.

## Откуда взяты эти практики

Это не теория. Они из реальной оптимизационной работы в продакшн-кодовых базах. Несколько примеров:

![React Best Practices Examples](/images/articles/2026-01/react-best-practices-example.png)

### Слияние итераций цикла

Чат-страница сканировала один список сообщений восемь раз. Мы слили в один проход — при тысячах сообщений разница существенная.

### Параллелизация await

API ждал завершения одного вызова базы, прежде чем начать следующий, хотя зависимости не было. Параллельный запуск сократил общее ожидание вдвое.

### Ленивая инициализация состояния

Компонент на каждом рендере парсил JSON-конфиг из `localStorage`, хотя значение было нужно один раз при инициализации состояния. Оборачивание в колбэк (`useState(() => JSON.parse(...))`) убрало лишнюю работу.

### Waterfalls и bundle — детали

- Идентификация client-server waterfalls (монтирование компонента → fetch → монтирование дочернего → fetch); Server Components переносят fetching на сервер; `Promise.all` + встроенная дедупликация запросов React; паттерны `preload`; стриминг с Suspense.
- Меньше JavaScript напрямую улучшает TTI: Server Components там, где интерактивность не нужна; динамические импорты через `next/dynamic`; чистка неиспользуемых зависимостей; tree-shaking и антипаттерн barrel-файлов; оптимизация шрифтов и изображений.
- Ре-рендеры: композиция вместо тотального `React.memo` (лифтинг стейта, children as props), корректные массивы зависимостей, colocation стейта, разделение контекста, взвешенное `useMemo`/`useCallback`.
- Server Components: граница `"use client"`, передача серверных данных через props вместо повторного fetching'а, избегание импорта server-only модулей в клиентский код.

### Частые антипаттерны и фиксы

**Антипаттерн**: fetch в `useEffect` клиентского компонента на третьем уровне вложенности. **Фикс**: перенос fetching'а в Server Component уровня роута, данные вниз через props.

**Антипаттерн**: barrel-файл (`index.ts`), ре-экспортирующий всю библиотеку. **Фикс**: прямые импорты из файла компонента для tree-shaking.

**Антипаттерн**: тотальный `React.memo` как «оптимизация». **Фикс**: паттерны композиции, перестройка дерева.

## Инкрементальное внедрение

Не нужно применять все 40+ правил разом:

1. **Начните с waterfalls**: максимальный импакт и проще измерять — аудит network tab на цепочки последовательных запросов.
2. **Дальше bundle size**: анализируйте build output, найдите крупнейшие клиентские чанки, ищите возможности Server Components.
3. **Затем ре-рендеры**: React DevTools Profiler для поиска чрезмерно ре-рендерящихся компонентов.
4. **Внедряйте непрерывно**: новые фичи сразу по правилам — ретрофит сложнее, чем строить правильно.

Структурированный формат позволяет селективно грузить только релевантные правила: waterfall-правила при строительстве data-heavy страниц, bundle-правила при мобильной оптимизации, re-render-правила при интерактивном UI.
