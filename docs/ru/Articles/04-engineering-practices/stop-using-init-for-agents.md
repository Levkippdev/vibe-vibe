# Перестаньте использовать /init для AGENTS.md

**Оригинал: [Stop Using /init for AGENTS.md](https://addyosmani.com/blog/agents-md/) (Addy Osmani)**

## Проблема автогенерируемых AGENTS.md

Когда AI-кодинг-инструменты ввели команды вроде `/init` для автогенерации AGENTS.md (или CLAUDE.md, CURSOR.md и т.д.), это выглядело выигрышем продуктивности. Одна команда — файл контекста проекта — и AI-ассистент внезапно «понимает» вашу кодовую базу. Кроме того, что не понимает — не так, как вы надеялись.

Две статьи начала 2026-го квантифицировали то, что многие подозревали: автогенерированные контекстные файлы часто **деградируют** производительность AI-агентов вместо улучшения. Выводы совпали по нескольким моделям и агентным фреймворкам:

- Автогенерированные файлы добавляют в среднем **20%+ токен-оверхеда** к каждому взаимодействию
- Дополнительные токены состоят в основном из информации, которую модель и так может вывести из кодовой базы
- Результаты на кодинг-бенчмарках **снижались** при включении автогенерированных контекстных файлов по сравнению с их отсутствием

## Что /init реально производит

Запуская `/init` или эквивалентные команды автогенерации, вы обычно получаете:

- Описание проекта из README.md (который агент и так может прочитать)
- Листинг директорий (который агент и так может исследовать)
- Определённые языки и фреймворки (которые агент и так идентифицирует по расширениям и конфигам)
- Генерические конвенции кодинга (стандартные для языка или выводимые из существующего кода)
- Команды build и test (которые есть в package.json, Makefile и т.п.)

Иными словами, **большая часть контента избыточна**. AI-агент и так имеет доступ к той же информации через файловые инструменты. Скармливание ему резюме того, что он может обнаружить сам, не делает его умнее — просто делает каждый промпт длиннее и дороже.

## Проблема сигнал/шум

Реальный ущерб не только в стоимости токенов — это разбавление внимания. У языковых моделей конечное эффективное внимание внутри контекстного окна. Заполняя окно генерическим, выводимым контентом, вы снижаете способность модели фокусироваться на том, что реально важно: ваших проектных конвенциях и решениях.

Представьте онбординг нового разработчика. Дайте ему 50-страничный документ, где 80% — «JavaScript использует точки с запятой, а React использует JSX»: он просмотрит всё мельком и пропустит те 20%, что содержат действительно важное проектное знание — вроде «мы используем кастомный error boundary с логированием в Sentry» или «все миграции базы должны быть обратно-совместимыми».

## Как писать эффективный AGENTS.md

Эффективный AGENTS.md содержит **только информацию, которую агент не может вывести из кодовой базы**. Что туда belongs:

### Проектные конвенции

Документируйте конвенции, отклоняющиеся от дефолтов или неочевидные из кода:

- «Мы используем kebab-case для имён файлов, не дефолтный для фреймворка PascalCase»
- «Все API-ответы используют формат-конверт: `{ data, error, meta }`»
- «Feature flags управляются через LaunchDarkly, не через переменные окружения»

### Архитектурные решения

Фиксируйте решения, чей контекст один код не передаёт:

- «Мы выбрали SQLite вместо Postgres, потому что это работает на embedded-устройствах»
- «Директория `legacy/` использует другой паттерн — не рефакторьте её под `src/`»
- «Мы сознательно не используем ORM; предпочтителен raw SQL для видимости запросов»

### Паттерны тестирования

Специфицируйте неочевидные требования к тестам:

- «Интеграционные тесты обязаны использовать Docker-контейнер `test-db`, не моки»
- «Snapshot-тесты запрещены — используйте явные ассерты»
- «У всех API-эндпоинтов должны быть тесты и happy path, и ошибочного пути»

### Процедуры деплоя

Включайте деплой-контекст, влияющий на написание кода:

- «Это деплоится на Lambda — функции обязаны завершаться за 15 секунд»
- «Миграции базы запускаются автоматически при деплое; они должны быть обратно-совместимыми»
- «Переменные окружения задаются через Terraform, не вручную»

## Что исключить

Активно удаляйте или не включайте:

- Основы синтаксиса языка
- Дефолты фреймворков и стандартные паттерны
- Информацию из README.md, package.json или конфигов
- Генерические best practices (используйте strict mode TypeScript, пишите тесты и т.п.)
- Структуры директорий, которые агент исследует сам

## Зона 8KB

Исследования и практика сходятся: эффективные AGENTS.md конвергируют к **8KB или меньше**. Сверх этого вы почти наверняка включаете избыточное. Техники компрессии:

1. **Ссылки вместо повторения**: «Следуй паттернам в `src/api/users.ts` как каноническому примеру» лучше, чем воспроизводить весь паттерн.
2. **Декларативно, не объясняюще**: «Используй Zod для всей валидации входа» бьёт абзац о том, почему выбран Zod.
3. **Приоритизируйте по импакту**: Если агент ошибётся в одном — что дороже всего исправлять? Ставьте это первым.
4. **Версионируйте и подчищайте**: Ревьюьте AGENTS.md ежеквартально. Удаляйте ставшее стандартом или принуждаемое линтером.

## Ручной против автогенерированного: доказательства

В контролируемых экспериментах рукописные AGENTS.md на ~4–8KB стабильно обходили автогенерированные на ~20–40KB:

- **Процент завершения задач**: на 12% выше с рукописными
- **Оценки качества кода**: рукописные файлы давали код, лучше соответствующий конвенциям проекта
- **Токен-эффективность**: на 25–35% меньше токенов на задачу
- **Частота ошибок**: меньше нарушений конвенций и архитектурных несовпадений

Вывод ясен: маленький, курированный контекстный файл бьёт большой автогенерированный всегда. Агенту не нужна карта всего леса — ему нужно знать, где ловушки.

## Практическая миграция

Если вы сейчас используете автогенерированный AGENTS.md:

1. **Аудит**: Прочитайте каждую строку. Для каждой спросите: «Может ли агент вывести это, читая мой код?» Если да — удалите.
2. **Добавьте недостающее**: Вспомните последние 5 раз, когда AI ошибся в вашем проекте. Напишите правила, предотвращающие те ошибки.
3. **Тест**: Прогоните один промпт со старым файлом и с новым. Сравните выводы. Постройный файл должен давать более проектно-уместные результаты.
4. **Обязательство поддержки**: Устаревший AGENTS.md хуже отсутствия. Держите его актуальным по мере эволюции проекта.

## Итог

Автогенерированные AGENTS.md — ловушка «дефолтных настроек» AI-разработки. Они ощущаются продуктивными — вы запустили команду и получили файл — но активно вредят качеству взаимодействий с AI. Выделите время написать сфокусированный, проектно-специфичный контекстный файл. Ваше будущее вы (и бюджет токенов) скажут спасибо.
