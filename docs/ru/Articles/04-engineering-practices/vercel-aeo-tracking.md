# Как Vercel построил AEO-трекинг для кодинг-агентов

**Оригинал: [How We Built AEO Tracking for Coding Agents](https://vercel.com/blog/how-we-built-aeo-tracking-for-coding-agents) (Eric Dodds, Allen Zhou)**

## Что такое AEO?

Если SEO (Search Engine Optimization) — про то, чтобы ваш контент находили поисковики, то **AEO (Agent Experience Optimization)** — про то, чтобы ваша инфраструктура, API и документация хорошо работали для AI-агентов. Кодинг-агенты становятся основным потребителем дев-инструментов и платформ — понимание того, как они взаимодействуют с вашими системами, уже не опция, а конкурентная необходимость.

Vercel распознал этот сдвиг рано: кодинг-агенты — одни из самых активных «юзеров» платформы. Они деплоят приложения, читают документацию, зовут API и взаимодействуют с дашбордами — всё программно. Трекинг и оптимизация этих взаимодействий требуют фундаментально иного инструментария, чем традиционная аналитика юзеров.

## Почему трекинг важен

Традиционные аналитические инструменты построены вокруг паттернов человеческого взаимодействия: просмотры страниц, CTR, длительность сессий. AI-агенты взаимодействуют с инфраструктурой принципиально иначе:

- **Нет сессий**: Агент делает дискретные API-вызовы, не «бродит» по сайту
- **Нет UI**: Агенты не видят ваш дашборд — они потребляют API-ответы и документацию
- **Много объёма, мало разнообразия**: Агенты часто делают много похожих запросов подряд
- **Успех бинарен**: Агент либо завершил задачу, либо нет. Поведения «просто посмотреть» нет

Без специализированного трекинга вы слепы к тому, как агенты ощущают вашу платформу. Не отличить, мучаются ли они с дизайном API, недопонимают ли документацию или бьются о rate limits, молча деградируя в производительности.

## Техническая архитектура

AEO-система Vercel построена на трёх ключевых компонентах:

### Sandbox для безопасного исполнения

Vercel Sandbox даёт изолированные окружения, где кодинг-агенты запускают код, тестируют деплои и работают с API платформы безопасно. С точки зрения AEO, Sandbox — контролируемая точка наблюдения:

- Каждое действие агента внутри Sandbox логируется с полным контекстом
- Потребление ресурсов (CPU, память, сеть) трекается по агентной сессии
- Провалы фиксируются с полными stack trace'ами и состоянием окружения
- Поведение агента можно воспроизвести для дебага и оптимизации

### AI Gateway для роутинга запросов

AI Gateway стоит между кодинг-агентами и backend-сервисами Vercel, давая единый слой наблюдения:

- **Классификация запросов**: Автоматически определяет, пришёл ли запрос от человека, AI-агента или автопайплайна
- **Агентная фингерпринтинг**: Идентифицирует, какой агентный фреймворк делает запросы (Claude Code, Cursor, Copilot, кастомные агенты) по паттернам и заголовкам
- **Роутинг запросов**: Оптимизирует формат и контент ответа под возможности запрашивающего агента
- **Rate limiting**: Агентно-осведомлённые лимиты, учитывающие burst-ную, параллельную природу агентных запросов

### Workflows для оркестрации

Vercel Workflows управляют многошаговыми взаимодействиями агентов — деплои, тест-прогоны, генерации превью — как first-class трекаемыми сущностями:

- Каждый шаг воркфлоу индивидуально таймируется и мониторится
- Зависимости между шагами явно моделируются
- Провал любого шага захватывает контекст всего воркфлоу, не только упавшего шага
- Паттерны воркфлоу между агентами анализируются для поиска частых последовательностей и бутылочных горлышек

## Сбор данных

### Агентная фингерпринтинг

Идентификация, какой агент делает запрос — фундамент AEO-трекинга. Vercel использует комбинацию сигналов:

- **User-Agent заголовки**: Многие агенты себя идентифицируют, но не консистентно
- **Паттерны запросов**: У разных агентов характерные последовательности (Claude Code склонен читать структуру проекта до изменений)
- **Контекст аутентификации**: API-ключи и токены ассоциированы с конфигурациями агентов
- **Поведенческие сигнатуры**: Тайминг запросов, паттерны конкурентности и ретраев создают опознаваемые фингерпринты

### Паттерны запросов

AEO-трекинг захватывает не только отдельные запросы, но паттерны между ними:

- **Анализ последовательностей**: Как выглядит типичный агентный воркфлоу? (Чтение доков → вызов API → проверка ответа → retry при провале)
- **Параллелизм**: Сколько конкурентных запросов делает агент? Уважает ли лимиты конкурентности?
- **Восстановление после ошибок**: Встретив ошибку, что делает агент? Retry? Другой подход? Сдаётся?

### Успехи и провалы

Каждое взаимодействие агента классифицируется как успех или провал:

- **Завершение задачи**: Достиг ли агент заявленной цели (задеплоить приложение, обновить конфиг, прочитать документацию)?
- **Частичный успех**: Завершил ли некоторые шаги, но провалил другие?
- **Таксономия провалов**: Почему агент провалился? (API-ошибка, проблема аутентификации, rate limit, двусмысленность документации, timeout)

## Метрики, которые важны

Строя AEO-трекинг, Vercel выявил метрики, прямее всего предсказывающие удовлетворённость и эффективность агентов:

### Task Completion Rate

Процент инициированных агентами воркфлоу, достигающих целевого конечного состояния. Это north star метрика AEO — если агенты не завершают задачи на вашей платформе, они (и их юзеры) уйдут в другое место.

### Токен-эффективность

Сколько токенов потребляет агент на конкретную задачу? Меньше — лучше. Высокое потребление обычно означает, что агент мучается: перечитывает документацию, ретраит проваленные запросы, исследует тупики.

### Паттерны ошибок

Не просто rate ошибок, но кластеризация. Один API-эндпоинт, вызывающий 80% агентных провалов — ясная цель оптимизации. Паттерны ошибок также вскрывают пробелы документации: если агенты стабильно неверно используют параметр API — документация этого параметра требует улучшения.

### Time to Completion

Сколько времени агент тратит на стандартную задачу? Эта метрика вместе с токен-эффективностью раскрывает, обусловлены ли трудности агентов сложностью (легитимно длинные задачи) или трением (ненужные ретраи и блуждания).

## Детали имплементации

AEO-пайплайн обрабатывает миллионы событий ежедневно:

1. **Ingestion**: Сырые события из Sandbox, AI Gateway и Workflows собираются в единый event stream
2. **Enrichment**: События обогащаются идентификацией агента, контекстом воркфлоу и данными аккаунта
3. **Aggregation**: События агрегируются в агентные сессии, завершения воркфлоу и временные ряды метрик
4. **Storage**: Агрегированные данные питают realtime-дашборды и долгосрочное аналитическое хранилище
5. **Analysis**: Автоматический anomaly detection помечает внезапные изменения поведения агентов или success rate

## Дашборды и алертинг

Vercel построил дашборды под задачи AEO:

- **Дашборд здоровья агентов**: Realtime-вид success rate, error rate и активных сессий агентов
- **Воронка воркфлоу**: Визуализирует, где агенты выпадают из многошаговых воркфлоу — как маркетинговая конверсионная воронка
- **Эффективность документации**: Трекает, какие страницы доков агенты читают чаще и коррелирует ли это с успехом задач
- **Правила алертов**: Автоматические алерты при падении success rate ниже порога, появлении новых паттернов ошибок или неожиданных всплесках потребления токенов

## Как AEO-инсайты улучшают разработку продукта

AEO-трекинг — не просто мониторинг, а продуктовая петля фидбека:

- **Дизайн API**: Когда агенты мучаются с API — это часто вскрывает проблемы дизайна, которые люди молча обходят. Фиксы улучшают опыт всех.
- **Документация**: Данные взаимодействий агентов точно показывают, какие доки полезны, а какие запутывают. Страницы, которые агенты посещают раз за разом без успеха в задаче, нужно переписывать.
- **Сообщения об ошибках**: Генерические ошибки, которые люди интерпретируют по контексту, для агентов бесполезны. AEO-данные ведут инвестиции в структурированные, машино-парсабельные ответы.
- **Rate limiting**: Традиционные лимиты под человеческие паттерны не учитывают агентное burst-поведение. AEO-данные формируют агентно-осведомлённые политики.

## Большая картина

AEO-трекинг — фундаментальный сдвиг в том, как платформы думают о юзерах. AI-агенты становятся основным интерфейсом между разработчиками и инструментами — оптимизация опыта агентов есть оптимизация опыта разработчиков. Инвестиция Vercel в AEO — не только понимание текущего поведения агентов, но строительство инфраструктуры под будущее, где агенты — first-class граждане платформы.
