# E. API-ключи, переменные окружения и базовая безопасность

Базовая версия не требует сразу учить полную систему безопасности, но есть несколько минимальных базовых практик, которые лучше завести как можно раньше.

## Сначала запомните самую важную фразу

> Не кладите API Keys напрямую в код repository.

Это может выглядеть просто, но это крайне важно. На базовом этапе многие проблемы безопасности возникают не потому, что принципы слишком сложны, а потому, что самые базовые границы не были соблюдены.

## Что такое `.env`

`.env` можно воспринимать как: место, специально предназначенное для хранения конфигурационных значений, которые вообще не следовало писать прямо в код.

Например:

- API Keys
- URL подключения к базе данных
- Секреты сторонних сервисов

Эти значения часто различаются по окружению и не подходят для хардкода в проект.

## Что такое `.gitignore`

Назначение `.gitignore` простое: оно говорит Git, какие файлы не должны попадать в repository.

Одна из важнейших привычек базового этапа — убедиться, что файлы вроде `.env` не закоммичены.

## Как минимум проверьте это перед выходом в свет

- API Keys не захардкожены в исходном коде
- Локальные чувствительные файлы вроде `.env` не попали в repository
- Переменные окружения, необходимые платформе deploy, настроены верно
- Если в production не хватает ключа — страница не делает вид, что работает нормально

## Очень практичный проверочный вопрос

Если не уверены, не хранит ли текущий проект секреты не там, можно спросить AI прямо:

```text
Помоги проверить, не записана ли в этом проекте чувствительная информация
прямо в коде.
Сфокусируйся на API Keys, переменных окружения и конфиг-файлах,
которые не должны попадать в repository.
Если найдёшь проблемы — скажи, как мне их исправить.
```

## На чём базовая версия здесь останавливается

Базовая версия лишь просит завести базовое чутьё. Она не углубляется здесь в полную систему аутентификации, дизайн прав доступа или более сложные стратегии безопасности.
