# Full-stack AI SaaS для оптимизации резюме

> Автор: Luochen · Целевая аудитория: разработчики, прошедшие базовый и продвинутый разделы туториала.
> Таймлайн: примерно 1 неделя от концепции до задеплоенного MVP.

## Почему оптимизация резюме?

До единой строчки кода поговорим, почему этот рынок стоит строить под него.

### Валидация рынка

Цифры рассказывают убедительную историю:

- **$1.6 млрд** — глобальный размер рынка резюме-билдеров в 2024
- **$3.1 млрд** — прогнозируемый размер рынка к 2032
- **Rezi.ai** — 3.3 млн юзеров и растёт
- **Teal HQ** — привлек $20.7 млн инвестиций

Это не спекулятивные «может, AI тут пригодится». Люди уже платят за помощь с резюме, и рынок удваивается менее чем за десятилетие. Вопрос не «есть ли спрос» — а «сможете ли вы построить что-то отличающееся».

### Чем AI-оптимизация резюме отличается?

Большинство резюме-инструментов делают поверхностное форматирование. AI-оптимизатор идёт глубже: анализ job-описаний, выявление пропущенных ключевых слов, скоринг релевантности, конкретные улучшения. Вот такой продукт мы строим.

## Фаза 1: требования — определяем MVP

### Используем фреймворк JTBD

Фреймворк Jobs-To-Be-Done помогает понять, что юзерам действительно нужно. Ключевой инсайт:

> **Юзеры хотят не «лучшее резюме». Они хотят интервью.**

Это переворачивает всё. Грамматические фиксы и форматирование приятны, но не за них платят. Юзеры хотят знать:

1. Насколько моё резюме соответствует этой конкретной вакансии?
2. Каких ключевых слов мне не хватает?
3. Что изменить, чтобы пройти ATS (Applicant Tracking Systems)?
4. Как подать мой опыт, чтобы совпасть с тем, что ищет работодатель?

### Срезаем до ядра MVP

От инсайта JTBD — вот что входит в наш MVP, а что нет:

**В scope (MVP):**
- Вставка текста резюме + целевого job-описания
- AI-анализ: match-скор, пропущенные ключевые слова, фидбек по секциям
- AI-оптимизированный вывод резюме
- Стриминговый ответ для realtime-фидбека

**Вне scope (будущие итерации):**
- Аккаунты юзеров и сохранённые резюме
- Загрузка/парсинг PDF
- Несколько версий резюме
- Платёжная обработка
- Интеграция с job-бордами

Цель — доказать ключевую ценность («AI может осмысленно улучшить ваше резюме под конкретную вакансию») в простейшей форме.

## Фаза 2: промпт-инжиниринг

AI-промпт — сердце продукта. Поймаете — и оптимизация ощущается магией. Промахнётесь — и это просто ещё один чат-бот.

### Проектирование системного промпта

Мы хотим, чтобы AI выступал как **старший технический рекрутер** — тот, кто просмотрел тысячи резюме и точно знает, что ищут найминг-менеджеры и ATS-системы.

Вот структура ядра промпта:

```
You are a senior technical recruiter with 15 years of experience
reviewing resumes for top tech companies.

Given a resume and a target job description, provide:

1. **Match Score** (0-100): How well the resume matches the job
2. **Missing Keywords**: Critical terms from the job description
   that are absent from the resume
3. **Section Analysis**: For each resume section (Summary,
   Experience, Skills, Education), provide specific feedback
4. **Optimized Content**: A rewritten version of the resume
   optimized for this specific job

Output format: JSON with the following structure:
{
  "score": number,
  "missingKeywords": string[],
  "analysis": {
    "summary": string,
    "experience": string,
    "skills": string,
    "education": string
  },
  "optimizedContent": string
}

Rules:
- Never invent experience the candidate doesn't have
- Focus on rephrasing and reorganizing existing experience
- Prioritize ATS compatibility
- Be specific in feedback — "add more metrics" is too vague,
  "quantify the user growth you drove in Q3" is actionable
```

### Выбор модели

Для проекта мы используем модель **Moonshot v1-8k** (через Kimi K2), но архитектура поддерживает замену на любой OpenAI-совместимый API. Ключевые соображения:

- **Окно контекста**: 8K токенов достаточно для большинства резюме + job-описаний
- **JSON-вывод**: модель надёжно выдаёт структурированный JSON по инструкции
- **Стоимость**: значительно дешевле GPT-4 при большом объёме
- **Скорость**: достаточно быстрая для стриминга

### Тестирование промпта

До построения приложения тестируйте промпт обширно:

1. Попробуйте разные форматы резюме (технические, креативные, управленческие)
2. Протестируйте разные job-описания (стартапы, энтерпрайз, разные роли)
3. Проверьте, что JSON-вывод стабильно парсится
4. Убедитесь, что опыт никогда не выдумывается

Итерация промпта дешева. Шипьте промпт, когда он стабильно работает на минимум 10-15 разнообразных кейсах.

## Фаза 3: full-stack реализация

### Тех-стек

| Слой | Технология | Почему |
|---|---|---|
| Фреймворк | Next.js 14 (App Router) | Full-stack в одном проекте |
| UI | Shadcn UI + Tailwind CSS | Профессиональные компоненты, быстрая стилизация |
| AI-интеграция | Vercel AI SDK (`streamText`) | Первоклассная поддержка стриминга |
| API-роут | `/api/optimize` | Защита API-ключа на сервере |
| Модель | moonshot-v1-8k | Дёшево, надёжный JSON-вывод |
| Деплой | Vercel | Zero-config хостинг Next.js |

### Настройка проекта

```bash
npx create-next-app@latest ai-resume-optimizer
cd ai-resume-optimizer

# Install dependencies
npm install ai @ai-sdk/openai
npx shadcn-ui@latest init
```

### Построение frontend

У UI три состояния:

**Состояние 1: ввод**
- Две большие текстовые области: «Ваше резюме» и «Job-описание»
- Заметная кнопка «Optimize My Resume»
- Чистый, профессиональный дизайн — это карьерный инструмент, не игрушка

**Состояние 2: анализ**
- Стриминговый ответ в реальном времени
- Юзеры видят, как AI «думает» — это строит доверие и вовлечение
- Индикация прогресса по каждой секции анализа

**Состояние 3: результаты**
- Match-скор на видном месте (с цветовым кодированием: красный/жёлтый/зелёный)
- Пропущенные ключевые слова как кликабельные теги
- Анализ по секциям в раскрывающихся карточках
- Оптимизированное резюме в копируемом блоке
- Кнопка «Optimize Again» для итераций

Промптните AI-ассистента:

```
Create the main page at src/app/page.tsx for an AI resume optimizer.
Use Shadcn UI components (Card, Button, Textarea, Badge, Progress).

The page should have:
1. A hero section with the app title and value proposition
2. Two side-by-side textareas: "Your Resume" and "Target Job Description"
3. An "Optimize" button that's disabled when either textarea is empty
4. A results section that appears after optimization, showing:
   - A circular score indicator (0-100)
   - Missing keywords as badges
   - Section feedback in cards
   - The optimized resume in a copyable block
5. Use Vercel AI SDK's useChat or useCompletion for streaming
```

### Построение API-роута

Backend — единственный API-роут, оркестрирующий вызов AI:

```
Create src/app/api/optimize/route.ts that:

1. Accepts POST with { resume: string, jobDescription: string }
2. Validates both fields are non-empty
3. Constructs the system prompt for resume analysis
4. Uses Vercel AI SDK's streamText() to stream the response
5. Uses the moonshot-v1-8k model (OpenAI-compatible API)
6. Returns the streaming response

The API key should come from process.env.MOONSHOT_API_KEY.
Include rate limiting: max 5 requests per minute per IP.
```

### Обработка стримингового ответа

Стриминговый опыт критичен для вовлечения. Без него юзеры пялятся на спиннер 15-30 секунд — ощущается сломанным. Со стримингом они видят, как анализ строится в реальном времени — ощущается быстрым и впечатляющим.

Vercel AI SDK делает это простым:

```typescript
// Simplified example of the streaming pattern
import { streamText } from 'ai';
import { createOpenAI } from '@ai-sdk/openai';

const moonshot = createOpenAI({
  baseURL: 'https://api.moonshot.cn/v1',
  apiKey: process.env.MOONSHOT_API_KEY,
});

const result = streamText({
  model: moonshot('moonshot-v1-8k'),
  system: SYSTEM_PROMPT,
  prompt: `Resume:\n${resume}\n\nJob Description:\n${jobDescription}`,
});

return result.toDataStreamResponse();
```

### Рендеринг Markdown-вывода

Анализ AI содержит форматированный текст — буллеты, жирный, заголовки. Используйте `react-markdown` для корректного рендера:

```bash
npm install react-markdown
```

Применяйте Tailwind-класс `prose` для красивой типографики:

```tsx
<div className="prose prose-sm max-w-none">
  <ReactMarkdown>{analysisText}</ReactMarkdown>
</div>
```

## Фаза 4: продуктовое мышление

Построение фичи — половина битвы. Другая половина — чтобы оно ощущалось продуктом.

### Момент «Ага!»

Когда юзер видит свой match-скор и конкретные пробелы — он мгновенно понимает ценность. Это момент «ага!» — и весь UI должен проектироваться так, чтобы достигать его максимально быстро.

Решения дизайна, ускоряющие момент «ага»:

- **Без регистрации** для первой оптимизации
- **Скор появляется первым** в стриминговом ответе (до детального анализа)
- **Пропущенные ключевые слова визуальны** — цветные бейджи, не спрятанные в тексте
- **Сравнение до/после** — оригинал и оптимизированная версия рядом

### Трекинг вовлечения

Даже для MVP трекайте базовые метрики:

- Сколько оптимизаций в день?
- Какой % юзеров запускает вторую оптимизацию?
- Копируют ли юзеры оптимизированное резюме?
- Где юзеры отваливаются?

Эти метрики говорят, работает ли продукт — до инвестиций в продвинутые фичи.

### Freemium-модель

Естественный путь монетизации:

| Тир | Что входит | Цена |
|---|---|---|
| Free | 3 оптимизации/день | $0 |
| Pro | Безлимит + PDF-экспорт + история | $9.99/мес |
| Team | Мульти-юзеры + аналитика | $29.99/мес |

Начинайте с бесплатного для валидации спроса — платёж добавляйте при стабильных дневных активных юзерах.

## Частые ловушки и решения

### Приватность: анонимизируйте до API-вызовов

Резюме содержат чувствительную личную информацию — имена, телефоны, адреса, названия работодателей. До отправки текста резюме в любой AI API:

- Вырезайте или заменяйте персональные данные
- Используйте плейсхолдер-имена в промпте при необходимости
- Делайте политику приватности ясной для юзеров
- Рассмотрите локальный/self-hosted вариант для юзеров, чувствительных к приватности

::: warning Приватность данных важна
Данные резюме по природе чувствительны. Даже если вы доверяете AI-провайдеру — юзеры должны доверять вам. Будьте прозрачны: какие данные отправляются, куда идут, как долго хранятся.
:::

### Галлюцинации: никогда не выдумывать опыт

Главный риск AI-оптимизации резюме — AI выдумает опыт, которого у кандидата нет. Системный промпт обязан явно это запрещать:

- «Never add experience, skills, or achievements not present in the original resume»
- «Rephrase and reorganize — never invent»
- Валидируйте вывод: если оптимизированное резюме упоминает навык, которого нет в оригинале, помечайте

### Форматирование: Markdown + Prose

Сырой AI-вывод в web UI выглядит ужасно. Всегда рендерите через markdown-процессор с нормальными стилями. Связка `react-markdown` + Tailwind `prose` закрывает 95% потребностей форматирования.

### Деплой: переменные окружения

Классическая ошибка новичка: приложение работает локально, но падает в продакшене — потому что API-ключ не задан.

**Чеклист перед деплоем:**
- [ ] Добавьте `MOONSHOT_API_KEY` (или ключ вашего провайдера) в переменные окружения Vercel
- [ ] Проверьте, что ключ работает в продакшене (не только локально)
- [ ] Настройте обработку отсутствующих/невалидных ключей
- [ ] Протестируйте полный флоу на задеплоенном URL

1. Решает реальную проблему (оптимизация резюме под конкретные вакансии)

3. Имеет ясный путь монетизации
